Text alternative: Hermes, OpenClaw, and MemPalace currently lead the local agent-native quadrant. @chude/memory is strong on local inspection and governance but lower on agent-native integration today. Its target position is the same local quadrant with a stronger MCP/local-server surface, not the hosted SaaS quadrant occupied by Mem0, Zep, Cloudflare, and Supermemory.

Positioning is qualitative. The key issue is not whether memory has graph/ranking/governance code. It is whether an agent can use it as a native memory substrate with clear controls and proof.

Where memory Can Win

  • Deterministic replay: event envelopes plus projections are stronger trust primitives than prompt-only memory.
  • Zero hidden egress: remote providers and sync paths are explicitly consented and allowlisted.
  • Governed memory: suppress, invalidate, expire, review, consent, and provenance are central rather than afterthoughts.
  • Developer portfolio fit: inboxes, friction, cross-project continuity, and coding-agent context are first-class.
  • Local-first operations: SQLite, event logs, audit commands, backup/restore, and no hosted dependency by default.

Where It Loses Today

  • MCP/server gap: CLI-first means it is not yet agent-native in the current market sense.
  • Benchmark gap: competitors publish external benchmark claims; memory has internal evals only.
  • UX gap: Phase 42.5 exists because fresh-user flow and command ergonomics are not proven finished.
  • Interop gap: no first-class import/export bridge for MEMORY.md, DREAMS.md, MemPalace, Mem0, or graph artifacts.
  • Release gap: source WIP and installed package truth are not aligned.

What Not To Build

  • A generic hosted memory API. Mem0, Zep, Supermemory, and Cloudflare already have stronger distribution there.
  • A full autonomous-agent runtime. Hermes, OpenClaw, Letta, and Cloudflare Agents own that lane more naturally.
  • Fake benchmark parity. Do not compare internal fixtures to LongMemEval, LoCoMo, or vendor claims as if equivalent.
  • Silent dreaming. Governed consolidation is the point; hidden mutation would contradict the product's trust thesis.
  • Raw secret resolution. Keep authkey optional and capability-based.
