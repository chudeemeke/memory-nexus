# Phase 36.9-01 Plan: Coverage Runner Migration and Remediation

## Objective

Make the release coverage gate honest and WoW-compliant: statements, branches, functions, and lines must each be measured independently and pass at >=95%.

## Current Verified Baseline

Verification date: 2026-05-28

`bun run test:coverage` now runs the full suite through an Istanbul-instrumented Bun workspace:

- Tests: 3,762 pass, 0 fail.
- Statements: 91.05% (6,660 / 7,314), needs +289 covered statements.
- Branches: 82.30% (3,666 / 4,454), needs +566 covered branches.
- Functions: 94.70% (1,270 / 1,341), needs +4 covered functions.
- Lines: 91.55% (6,399 / 6,989), needs +241 covered lines.

This is a real release blocker. The prior Bun LCOV gate was insufficient because statements and branches were unavailable. Mapping statements to lines or branches to functions is explicitly forbidden.

## Implemented Runner Work

- Added `scripts/run-istanbul-bun-coverage.ts`.
- Added unit coverage for the runner in `scripts/run-istanbul-bun-coverage.test.ts`.
- Updated `package.json` so `bun run test:coverage` uses the Istanbul-backed Bun harness and then runs `scripts/check-coverage-thresholds.ts` against `coverage/coverage-summary.json`.
- The harness:
  - Copies the repo to a temp workspace outside the project tree.
  - Instruments production `src/**/*.ts`.
  - Seeds zero-count baseline coverage for every instrumented source file so unexecuted files count against the gate.
  - Links `node_modules` and `dist` into the temp workspace so existing artifact/dependency tests run unchanged.
  - Disables Bun native coverage in the temp workspace to avoid misleading two-metric output.
  - Emits Istanbul `coverage-summary.json` and `lcov.info`.

## Rejected Shortcuts

- `c8 bun test`: rejected because it emits `Unknown` totals for all metrics.
- Vitest-only migration: rejected as the first move because the release surface depends on Bun runtime APIs such as `bun:sqlite`, `Bun.file`, `Bun.write`, and `Bun.hash`.
- Metric aliasing: rejected because it would create false confidence and violate the 95%-each-metric rule.

## Test Strategy

- Prefer behavior tests through exported command/service functions.
- Use dependency injection seams already present before adding mocks.
- Add small seams only where side effects block behavior verification.
- Avoid tests that assert implementation detail only to satisfy coverage.
- Keep generated coverage tests under `*.coverage.test.ts`; they run but are excluded from production coverage accounting.

## Exit Criteria

- `bun run test:coverage` passes with all four metrics >=95%.
- `bun run typecheck` passes.
- `bun run build` passes.
- `bun run test:isolation` passes.
- `bun audit` passes.
- Planning state documents the final measured coverage numbers.
