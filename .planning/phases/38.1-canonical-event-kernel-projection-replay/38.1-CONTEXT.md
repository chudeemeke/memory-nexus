# Phase 38.1 Context: Canonical Event Kernel and Projection Replay

## Phase Boundary

Implement the canonical event kernel, migration path, machine/event identity value objects, integrity metadata, and projection registry needed before remote sync, persona, graph, ranking, or dreaming.

Do not implement remote sync in this phase.

## Locked Decisions From Phase 38.0

- Event envelopes are the source of truth; SQLite tables are projections.
- Event envelopes include event id, schema version, machine id, sequence, kind, operation, provenance, privacy, consent, causality, payload, and integrity metadata.
- Existing fact-shaped event records must migrate or replay without data loss.
- Projection registry replaces generic `rebuildProjections`.
- Domain layer remains dependency-free.
- Consent/provenance governance is promoted to Phase 38.2.5 and must be represented in event metadata.

## Event Envelope Requirements

Minimum fields:

- `schemaVersion`
- `eventId`
- `machineId`
- `sequence`
- `kind`
- `operation`
- `occurredAt`
- `observedAt`
- `scope`
- `provenance`
- `privacy`
- `consent`
- `causality`
- `payload`
- `integrity`

## Projection Registry Requirements

- Each projection declares consumed event kinds.
- Replay is deterministic.
- Corrupt event lines are quarantined or reported without silent mutation.
- Duplicate events are idempotent.
- Supersedence is represented as events, not synthetic fact metadata only.

## Migration Requirements

- Existing v1 fact-shaped JSONL events remain readable.
- Migration can produce v2 envelopes or replay v1 through an adapter.
- Data loss is a blocker.
- Migration tests must cover legacy add, legacy supersedence, missing metadata, and redaction metadata.
