# Plan 38.1-01: Canonical Event Kernel and Projection Replay

## Goal

Replace fact-shaped event-log coupling with a domain-owned, schema-versioned event envelope and deterministic projection replay, while preserving every existing event-log compatibility path.

## Scope

- Add domain value objects/types for memory event envelopes, identity, causality, provenance, privacy, consent, and integrity metadata.
- Add v1 fact-record adapter so existing JSONL records replay without data loss.
- Add v2 envelope append/read support while keeping the existing `appendEvent`, `readEvents`, and `rebuildProjections` compatibility APIs.
- Add a projection registry that declares consumed event kinds and replays canonical envelopes deterministically.
- Quarantine/report malformed or invalid event lines without silent mutation.

## Non-Scope

- No remote sync enablement.
- No remote CLI surface changes.
- No provider egress policy implementation beyond event metadata representation.
- No graph/persona/ranking/dreaming projections.

## TDD Steps

1. RED: domain event envelope tests for required fields, validation, stable identity, privacy/provenance/consent, duplicate sequence rejection, and integrity hashing.
2. RED: event-log tests for v2 append/read, v1 migration, malformed-line quarantine, out-of-order deterministic replay, duplicate idempotency, supersedence projection, and redaction metadata preservation.
3. GREEN: implement domain kernel and v1/v2 JSONL adapter.
4. GREEN: replace `rebuildProjections` internals with projection registry while preserving public compatibility functions.
5. REFACTOR: keep domain dependency-free and infrastructure-specific I/O inside `src/infrastructure/database/event-log.ts`.
6. VERIFY: targeted tests, typecheck, build, test isolation, coverage gate, audit, and gitleaks when source changes are complete.

## Acceptance Gates

- `MemoryEventEnvelope` validation rejects missing identity, invalid sequence, invalid dates, invalid scope, missing provenance, missing privacy/consent, and integrity mismatches.
- Existing v1 fact-shaped records replay into facts with the same uuid, type, project, content, metadata, observed time, supersedence state, and redaction metadata.
- v2 records replay from canonical envelopes and deduplicate repeated event ids.
- Projection registry declares consumed kinds and rebuilds the facts projection deterministically.
- Corrupt/invalid lines are reported to a structured replay report or console compatibility path, never silently swallowed.
- Remote sync remains gated by `MEMORY_EXPERIMENTAL_REMOTE_SYNC=1`; this phase does not register or enable it.
