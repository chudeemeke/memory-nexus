  <action>
    **Root cause (per D-05):** The Transformers.js library emits multiple progress events for different files during model download. Some files (config.json, tokenizer.json) have small or zero `total` values. The current handler on line 364-365 starts the bar with whatever `total` value comes in the first "downloading" event, which may be 0.

    **Fix createModelDownloadHandler in progress-reporter.ts (lines 350-374):**

    Replace the current TTY handler implementation:

    ```typescript
    // TTY: show animated progress bar for download
    const chars = getBarCharacters();
    const downloadBar = new cliProgress.SingleBar({
      format: "Downloading model |{bar}| {percentage}% | {value}/{total} MB",
      barCompleteChar: chars.complete,
      barIncompleteChar: chars.incomplete,
      hideCursor: true,
    });
    let started = false;
    let maxTotal = 0;

    return (progress: DownloadProgress) => {
      if (progress.status === "downloading") {
        const loadedMb = Math.round(progress.loaded / 1048576);
        const totalMb = Math.round(progress.total / 1048576);

        // Track the largest total seen (the model file is the big one)
        if (totalMb > maxTotal) {
          maxTotal = totalMb;
        }

        if (!started && maxTotal > 0) {
          downloadBar.start(maxTotal, loadedMb);
          started = true;
        } else if (started) {
          // Update total if a larger file was discovered
          downloadBar.setTotal(maxTotal);
          downloadBar.update(loadedMb);
        }
      } else if (progress.status === "ready" && started) {
        downloadBar.stop();
      }
    };
    ```

    Key changes:
    1. Track `maxTotal` across all progress events
    2. Only start the bar when `maxTotal > 0` (skip 0-byte initial events)
    3. Use `downloadBar.setTotal(maxTotal)` to update total dynamically as larger files are discovered

    - Testing with a mock/spy on cliProgress.SingleBar to verify start/update/setTotal/stop calls
    OR, if mocking is too complex, extract the total-tracking logic into a pure function `trackDownloadTotal(currentMax: number, newTotal: number): number` and test that directly.
