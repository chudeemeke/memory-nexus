<objective>
Normalize the `--format` option across all 6 query commands. Today's surface is inconsistent:
- search / list / show / stats: `.choices(["default", "ai"]).default("default")`
- context / related: `.choices(["brief", "detailed", "ai"]).default("brief")`

Phase 32 normalizes to `["brief", "ai"]` on all 6 commands (no `.default()` — undefined = current text default). Each command gets a `brief` formatter path. `--format detailed` is retained on context AND related ONLY as a deprecated alias (mapped to existing behavior, CHANGELOG note for removal in next minor).

Purpose: Satisfy CLI-03 with a uniform mode taxonomy ready for Phase 32.5 (which may add a third `shape` mode).
Output: Six modified command files; six modified per-command test files; four formatter files extended with `brief` mode; CHANGELOG entry for the deprecation.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI `--format <type>` user input | Commander `.choices()` validates against allowed list; invalid values rejected pre-action |
| Formatter brief output → terminal | Brief output contains user-derived strings (snippets, project names) |
| Deprecation warning → stderr | Static string; no user data interpolated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-08 | Tampering | Crafted snippet containing ANSI escape sequences slipping through `--format brief` (which does NOT call `formatForAi`) | mitigate | The brief output `.replace(/<\/?mark>/g, "")` strips FTS markup; if upstream emits raw ANSI in snippets, it passes through. ACCEPTED RISK: snippets in memory-nexus DB come from JSONL session capture, not network input; if a session contained ANSI codes (e.g., a tool output), they were already in the user's terminal history. Local-only CLI; no privilege escalation. Mitigation: existing color-aware formatters already handle this in default mode. |
| T-32-09 | Information Disclosure | Brief output truncation cutting mid-token leaking partial sensitive data (e.g., partial API key) | accept | Brief output truncates snippets to 80 chars; if a snippet contains "Bearer eyJ..." it shows the first 80 chars. The data was already in stdout for the user (it's their session history). No new exposure vs default text mode. |
| T-32-10 | Repudiation | Deprecation warning hiding the fact that `--format detailed` was used (no log) | accept | One-shot stderr warning is observable to the user; not logged externally. Audit trail not required for a local CLI. |
| T-32-11 | Tampering | `options.format === "default"` checks in legacy code paths silently breaking after normalization | mitigate | Per RESEARCH Pitfall 2: Task 3 grep + migrate all `=== "default"` checks. Tests in Task 1 catch regressions on undefined `format`. |

ASVS V5 (Input Validation): Commander's `.choices(["brief", "ai"])` validates `--format` at parse time. Invalid values return exit code 1 with Commander's standard error. No additional validation needed in handlers.
