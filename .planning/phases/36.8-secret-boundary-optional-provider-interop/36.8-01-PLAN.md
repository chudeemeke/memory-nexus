# Plan: Phase 36.8 - Secret Boundary and Optional Provider Interop

## Objective

Restore release gates and harden the v4 foundation before Phase 37. The phase explicitly treats current failures and pre-existing security gaps as in-scope product issues, not incidental cleanup.

## Invariants

- `memory-nexus` must work without `authkey`.
- `authkey` may improve runtime secret injection, but `memory-nexus` must not call `authkey get` or resolve raw secrets through an AI-visible path.
- Secrets and sensitive transcript material must be classified/redacted before persistence, extraction, embedding, export, remote sync, or logs.
- Dirty remote-sync work must not broaden the v4 release surface until its architecture has a separate v5 plan.
- Gates must be honest. A command that returns success while hiding type errors is a failing gate.

## Execution Order

### R0 - Restore Gate Honesty

1. Fix current TypeScript failures.
   - Remove unused imports.
   - Respect `exactOptionalPropertyTypes` by omitting absent optional fields instead of assigning `undefined`.
2. Fix build masking.
   - Remove `|| true` from type generation.
   - Ensure `bun run build` fails when `tsc` fails.
3. Restore test isolation.
   - Replace first-party `mock.module` in sync remote tests with a deps-parameter seam.
   - Keep user-facing options separate from operational dependencies.
4. Quarantine v5 remote-sync risk.
   - Leave code testable if already present, but prevent it from silently expanding the v4 publish surface.
   - Any remote operation must stay disabled unless explicitly configured.
5. Re-run:
   - `bun run typecheck`
   - `bun run build`
   - `bun run test:isolation`

### R1 - Secret Boundary

1. Add a redaction port in the domain layer.
   - The application layer depends on the port, not infrastructure regexes.
2. Add a default infrastructure adapter.
   - Detect common API keys, bearer tokens, JWTs, PEM blocks, AWS credentials, GitHub tokens, and env assignment patterns.
   - Return redacted text plus findings metadata; never return raw secret values as findings.
3. Apply redaction before new persistence writes.
   - Message content.
   - Tool inputs.
   - Tool results.
   - Extracted facts where source content may include secrets.
4. Apply redaction before provider egress.
   - Embedding request text.
   - Extraction-provider message payloads.
5. Add regression tests.
   - Tests verify raw secret substrings are absent from persisted content and provider payloads.

### R2 - Provider Secret Configuration

1. Add env/ref based provider credential fields.
   - Prefer `embedding.apiKeyEnv` and process environment.
   - Allow opaque `embedding.apiKeyRef` for display/config intent only.
   - Keep `embedding.apiKey` as deprecated compatibility input with warning and migration path.
2. Update CLI provider resolution.
   - Environment injection works naturally with `authkey run --env memory -- memory extract ...`.
   - Missing referenced keys produce actionable errors without printing secret values.
3. Add tests for precedence and no-secret output.

### R3 - Optional authkey Interop Documentation

1. Keep `docs/plans/2026-05-27-authkey-optional-integration.md` as the roadmap source.
2. Add user-facing docs for safe operation:
   - `authkey run --env memory -- memory sync --embed`
   - `authkey run --env memory -- memory extract <project>`
3. Explicitly document prohibited coupling:
   - No `authkey get`.
   - No raw secret resolver inside memory-nexus.
   - No production dependency until authkey readiness gates pass.

### R4 - Verification and State

1. Run full gates:
   - `bun test --timeout 15000`
   - `bun run typecheck`
   - `bun run build`
   - `bun run test:isolation`
   - `bun audit`
   - `gitleaks detect --no-banner --redact --source .`
2. Update `.planning/STATE.md` with the exact pass/fail truth.
3. If any gate remains failing, document concrete owner, trigger, and next action. Do not mark Phase 36.8 complete.

## Acceptance Criteria

1. Release cannot proceed while build/typecheck/isolation/audit failures are hidden.
2. New ingested transcript/tool content containing realistic secret-shaped values stores only redacted values.
3. Remote provider calls receive redacted payloads by default.
4. Provider credentials can be supplied by environment injection without storing plaintext keys in config.
5. `authkey` is represented as optional capability interop, not a hard dependency.
6. Full verification output is recorded in planning state.

## Implementation Notes

- Export redaction is enabled in the CLI by default. `--include-sensitive` is the explicit raw-backup opt-in.
- `apiKeyRef` is intentionally not a resolver. It is metadata for doctor/status and future masked capability interop.
- Remote sync remains disabled unless explicitly configured and is not expanded into the v4 publish surface by this phase.
