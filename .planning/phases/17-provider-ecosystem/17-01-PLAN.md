# Plan 17-01: OpenAI and Ollama Provider Adapters with Config and Factory Wiring

## Goal

Implement OpenAI and Ollama embedding provider adapters that the factory can create from config, with `apiKey` and `baseUrl` config fields, updated doctor readiness checks, and full test coverage.

## Context

Phase 14 established:
- `IEmbeddingProvider` port in domain layer (`src/domain/ports/embedding.ts`)
- `TransformersJsProvider` adapter (`src/infrastructure/embedding/transformers-js-provider.ts`)
- `EmbeddingProviderFactory` with switch/cache pattern (`src/infrastructure/embedding/embedding-provider-factory.ts`)
- `EmbeddingConfigData` interface in config-manager (`src/infrastructure/hooks/config-manager.ts`)
- `EmbeddingHealth` interface and `checkEmbeddingConfig()` in health-checker

The factory currently only handles `"local"` provider. This plan adds `"openai"` and `"ollama"` cases, extends config with `apiKey`/`baseUrl`, and adds provider readiness to doctor output.

Neither OpenAI nor Ollama require npm dependencies. Both use native `fetch()` against simple HTTP endpoints.

## must_haves

- OpenAI provider implements IEmbeddingProvider with embed(), embedBatch(), initialize(), dispose(), isReady()
- Ollama provider implements IEmbeddingProvider with embed(), embedBatch(), initialize(), dispose(), isReady()
- EmbeddingConfigData interface has optional `apiKey` and `baseUrl` fields
- Factory creates OpenAI provider when config.provider === "openai"
- Factory creates Ollama provider when config.provider === "ollama"
- Factory error message lists all three supported providers: local, openai, ollama
- Doctor reports provider readiness status (ready/not-ready with reason)
- loadConfig() deep-merges new optional fields without breaking existing configs
- All tests pass with 95%+ coverage at each metric for new code

### Task 1: OpenAI and Ollama provider adapters (RED-GREEN)

Write failing tests first, then implement both provider adapters.

#### OpenAI Provider (`src/infrastructure/embedding/openai-provider.ts`)

**Test file:** `src/infrastructure/embedding/openai-provider.test.ts`

Tests to write (RED phase):
1. Constructor sets defaults: model = "text-embedding-3-small", dimensions = 1536, baseUrl = "https://api.openai.com/v1"
2. Constructor accepts custom model, dimensions, baseUrl, apiKey
3. isReady() returns false before initialize()
4. initialize() sets isReady() to true (no API call -- mark ready immediately per research anti-pattern guidance)
5. embed() throws "Provider not initialized" when called before initialize()
6. embed() calls fetch with correct URL, headers (Authorization Bearer), and body (model, input, dimensions)
7. embed() returns EmbeddingResult with correct embedding, model, and dimensions
8. embed() throws on non-OK response with status code and error body
9. embedBatch() sends array input in single request
10. embedBatch() returns results sorted by index (OpenAI returns data[] with index field)
11. embedBatch() throws on non-OK response
12. dispose() sets isReady() to false
13. name property returns "openai"

Implementation:
- Class `OpenAiProvider` implements `IEmbeddingProvider`
- Constructor: `{ apiKey: string; model?: string; dimensions?: number; baseUrl?: string }`
- Defaults: model = "text-embedding-3-small", dimensions = 1536, baseUrl = "https://api.openai.com/v1"
- `embed()`: POST to `${baseUrl}/embeddings` with `{ model, input: text, dimensions }`, Authorization header
- `embedBatch()`: POST with `input: texts` (array), sort response by `data[].index`
- Both methods construct `EmbeddingResult.create({ embedding: new Float32Array(data), model, dimensions })`
- Error handling: check `response.ok`, throw with status + body text

**Mock strategy:** Use `globalThis.fetch = mock(...)` in test setup (restore in afterEach). Return controlled JSON responses.

#### Ollama Provider (`src/infrastructure/embedding/ollama-provider.ts`)

**Test file:** `src/infrastructure/embedding/ollama-provider.test.ts`

Tests to write (RED phase):
1. Constructor sets defaults: model = "nomic-embed-text", dimensions = 768, baseUrl = "http://localhost:11434"
2. Constructor accepts custom model, dimensions, baseUrl
3. isReady() returns false before initialize()
4. initialize() calls GET `${baseUrl}/api/tags` to check server reachability
5. initialize() sets isReady() to true on successful response
6. initialize() throws with actionable error message on connection failure: "Cannot reach Ollama server at {url}. Ensure Ollama is running: ollama serve"
7. initialize() throws when server returns non-OK status
8. embed() throws "Provider not initialized" when called before initialize()
9. embed() calls POST `${baseUrl}/api/embed` with `{ model, input: text }`
10. embed() returns EmbeddingResult from `response.embeddings[0]`
11. embed() throws on non-OK response with status and body
12. embed() throws with "Model 'X' not found. Run: ollama pull X" hint when appropriate (404 or model-not-found in error body)
13. embedBatch() sends array input in single request `{ model, input: texts }`
14. embedBatch() returns results from `response.embeddings[]` array
15. embedBatch() throws on non-OK response
16. dispose() sets isReady() to false
17. name property returns "ollama"

Implementation:
- Class `OllamaProvider` implements `IEmbeddingProvider`
- Constructor: `{ model?: string; dimensions?: number; baseUrl?: string }`
- Defaults: model = "nomic-embed-text", dimensions = 768, baseUrl = "http://localhost:11434"
- `initialize()`: GET `${baseUrl}/api/tags` -- if unreachable, throw with recovery hint
- `embed()`: POST to `${baseUrl}/api/embed` with `{ model, input: text }`
- `embedBatch()`: POST with `input: texts` (array), map `response.embeddings[]` to EmbeddingResult array
- Error handling: check `response.ok`, parse error body for model-not-found hints

**Mock strategy:** Same `globalThis.fetch` mock pattern.
