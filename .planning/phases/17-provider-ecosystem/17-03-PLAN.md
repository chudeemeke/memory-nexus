<objective>
Fix provider-specific default resolution in config-manager so that switching provider from "local" to "openai" or "ollama" without explicitly setting model/dimensions applies the correct provider defaults instead of hardcoded local defaults.

Purpose: UAT test 3 found that `memory doctor` shows "Model: Xenova/all-MiniLM-L6-v2" and "Dimensions: 384" when provider is set to "openai" because loadConfig() deep-merges with DEFAULT_EMBEDDING_CONFIG which hardcodes local provider values. This would also cause the factory to pass the wrong model to the OpenAI API at runtime.

Output: Updated config-manager.ts with provider-specific default profiles and resolution logic. All downstream consumers (doctor, factory) automatically get correct values because they call loadConfig().
</objective>

GREEN phase -- Implement the fix:

In config-manager.ts, add:

1. Export a `PROVIDER_DEFAULTS` map (Record<string, {model: string, dimensions: number}>):
```typescript
export const PROVIDER_DEFAULTS: Record<string, { model: string; dimensions: number }> = {
    local: { model: "Xenova/all-MiniLM-L6-v2", dimensions: 384 },
    openai: { model: "text-embedding-3-small", dimensions: 1536 },
    ollama: { model: "nomic-embed-text", dimensions: 768 },
};
```

2. Export a `resolveProviderDefaults(merged: EmbeddingConfigData, userEmbedding: Partial<EmbeddingConfigData> | undefined): EmbeddingConfigData` function:
   - Takes the already-merged config and the raw user embedding section
   - If provider is NOT "local" (default changed), check if model/dimensions were user-explicit:
     - If userEmbedding has no `model` field: use PROVIDER_DEFAULTS[provider].model (fall back to merged.model if provider unknown)
     - If userEmbedding has no `dimensions` field: use PROVIDER_DEFAULTS[provider].dimensions (fall back to merged.dimensions if provider unknown)
   - If provider IS "local": return merged as-is (DEFAULT_EMBEDDING_CONFIG already correct)
   - Return the resolved config

3. Update loadConfig() to call resolveProviderDefaults after the deep-merge:
   - Extract `loaded.embedding` from the parsed JSON (before merge)
   - After computing the merged config, call `resolveProviderDefaults(merged.embedding, loaded.embedding)` and assign the result back to `merged.embedding`

The key insight: `loaded.embedding` is the RAW user JSON. If it does NOT have a `model` key, the user did not set it -- so provider defaults should apply. If it DOES have a `model` key (even if the value matches a default), the user explicitly chose it -- preserve it.

Use the `in` operator or Object.hasOwn() to check for field presence: `"model" in userEmbedding` returns true even if the value is the same as the default, which is the correct behavior.
