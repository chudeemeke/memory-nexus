# Phase 36.10-01 Summary: Legacy Memory File Publish Hardening

Status: Complete
Completed: 2026-05-30

## What Changed

- Added `legacyMemoryFiles.enabled` to runtime config with a default of `false`.
- Added `memory sync --include-memory-files` and `MEMORY_LEGACY_MEMORY_FILES=1` as explicit compatibility opt-ins for legacy markdown sidecar indexing.
- Changed `memory sync` so it no longer reads or indexes `~/.memory` / `MEMORY_HOME` by default.
- Added `memory backfill --write-memory-files` and the same env/config opt-in for legacy daily-log writes.
- Changed non-dry-run `memory backfill` to refuse legacy writes by default with an actionable error.
- Updated the PreCompact hook reminder so it no longer tells agents to write `~/.memory` files.
- Updated README, CHANGELOG, and the legacy agent-write protocol to describe memory files as compatibility-only.
- Fixed publish metadata by replacing the placeholder repository URL with the actual `chudeemeke/memory-nexus` remote.
- Hardened build output by cleaning `dist` before build, disabling declaration maps, and keeping Bun bundles sourcemap-free.

## Compatibility Contract

Legacy memory-file APIs and tables remain present for users who intentionally need them. The v4 default is SQLite/facts storage, not legacy markdown sidecars.

Supported legacy opt-ins:

- CLI: `memory sync --include-memory-files`
- CLI: `memory backfill --write-memory-files`
- Env: `MEMORY_LEGACY_MEMORY_FILES=1`
- Config: `legacyMemoryFiles.enabled=true`
