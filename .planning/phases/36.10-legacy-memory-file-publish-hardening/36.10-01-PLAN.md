# Phase 36.10-01 Plan: Legacy Memory File Publish Hardening

Status: Complete
Created: 2026-05-30

## Problem

The Phase 37 publish audit found that current source still reads `~/.memory` / `MEMORY_HOME` during `memory sync` and writes daily logs there through `memory backfill`, while Phase 35 and the current state claim the convention is deprecated and SQLite/facts are the default knowledge store.

Publishing with that mismatch would be dishonest and brittle: users would see an active legacy filesystem state layer while the architecture says facts/event logs are canonical.

## Goal

Make legacy memory-file behavior explicit opt-in before any npm publish. Keep compatibility for existing users, but default v4 behavior must not read from or write to `~/.memory` / `MEMORY_HOME`.

## Tasks

1. Add an explicit legacy-memory-file switch.
   - `memory sync` should only index legacy memory files when the user opts in.
   - Supported opt-ins: a CLI flag and an env/config path where appropriate.
   - Default behavior: no `~/.memory` / `MEMORY_HOME` scan.

2. Gate backfill writes.
   - `memory backfill` must not write to `~/.memory` / `MEMORY_HOME` by default.
   - Add an explicit opt-in flag for the legacy write path.
   - The refusal message must be actionable and must not imply silent data loss.

3. Preserve compatibility seams.
   - Keep domain/application memory-file types unless removing them is necessary; this phase is about default behavior and publish truth, not deleting historical capability.
   - Programmatic APIs that inject their own writer/scanner can remain testable.

4. Update public docs and release notes.
   - README must label memory files as legacy opt-in, not current default storage.
   - CHANGELOG must call out the default behavior change.

5. Verify.
   - Focused tests for default-off and explicit opt-in behavior.
   - `bun run typecheck`
   - `bun run build`
   - `bun run test:isolation`
   - `bun run test:coverage`
   - `bun audit`
   - `gitleaks detect --no-banner --redact --source .`

## Non-Goals

- Do not implement Phase 38 remote sync.
- Do not delete the memory-file database tables in this phase.
- Do not publish to npm from this phase.

## Acceptance

- `memory sync` default path no longer indexes legacy memory files.
- `memory backfill` default path no longer writes legacy daily logs.
- Legacy behavior requires explicit opt-in and is documented as legacy.
- The full release gate remains green.
