# Phase 42.5 Plan: Feature Completeness and UX Polish

Created: 2026-07-01
Status: active

## Goal

Ensure no stated, inferred, documented, prototype, disabled, or partial feature is removed or left ambiguous before the Phase 43 readiness gate. The outcome is not "more docs"; it is a reconciled product surface where fresh users, first-party tools, and agents can discover and operate the product safely.

## Invariants

- Preserve feature intent. Do not remove or quietly narrow a feature to make v5 easier to ship.
- Complete user-facing promises where the implementation cost is reasonable and the command belongs in the product.
- Explicitly own any larger deferred feature with a concrete later gate and a reason.
- Keep optional integrations optional. Core workflows must work without authkey, remote sync, or hosted providers.
- Prefer compatibility command surfaces over forcing users to remember historical command names.
- Every risky mutation needs a dry-run, preflight, confirmation, or clear no-op path where practical.

## Current Findings

The initial inventory found concrete PRD-to-CLI mismatches:

- PRD fresh-user flow names `memory backup create/verify` and `memory restore`, but the CLI exposes `export`, `import`, and `remote backup/restore`.
- PRD upgrade flow names `memory doctor --upgrade`, `memory migrate --dry-run --json`, `memory migrate --confirm`, and `memory projections rebuild --verify`, but those public command surfaces are missing or partial.
- `migrate --from-windows` exists as an option but the command implementation currently performs the same operation regardless of the option and lacks dry-run/JSON/confirm ergonomics.
- Phase 43 still has one contract-only eval fixture: `remote_sync_conflict`.
- README still says "16 commands" in one introductory paragraph, which is stale after v5.
- Market-fit review identifies MCP/server, benchmark, UX, interop, and release alignment gaps. Phase 42.5 owns only the UX/completeness subset and must explicitly hand off the rest to Phase 43/44.

## Work Plan

### 42.5-01 Inventory and Trace

1. Inventory current code/docs/roadmap/requirements/inbox/tests and disabled/prototype surfaces.
2. Trace each Product North Star claim to one of: implemented, implemented with caveat, Phase 42.5 fix, Phase 43 owner, Phase 44 owner, future non-goal.
3. Use Claude as a critical reviewer on the inventory and implementation order before command changes.

Deliverables:

- `FEATURE-INVENTORY.md`
- `NORTH-STAR-TRACE.md`
- Reviewed implementation order

### 42.5-02 Compatibility Command Surfaces

1. Add top-level `memory backup` and `memory restore` compatibility surfaces for local data backup/restore.
2. Add `backup create`, `backup verify`, and `restore <backup>` JSON/text behavior with dry-run and confirmation controls.
3. Add top-level `memory projections rebuild --verify` as the public projection verification/rebuild surface.
4. Extend `memory migrate` with `--dry-run`, `--json`, and `--confirm` behavior. Keep existing behavior compatible where safe.
5. Add `doctor --upgrade` as a readiness diagnostic path, not a mutation path.
6. Update shell completion, command grouping, programmatic exports, README, and reference docs for new surfaces.

### 42.5-03 Fresh-User UAT and Contract Polish

1. Add source-backed UAT tests for install-discovery/help, backup/restore dry-run, projection verification, migration dry-run, audit, and doctor upgrade surfaces.
2. Ensure JSON output has schema versions and stable command/kind fields where it is a contract.
3. Run fresh-user command smoke against temporary config/data dirs.
4. Update Phase 42.5 docs with exact evidence and remaining owned gaps.

## Out of Scope for Phase 42.5

- Implementing an MCP server or local daemon. Owned by Phase 43 as a readiness/positioning decision.
- Publishing external benchmark parity claims. Owned by Phase 43; internal evals must not be represented as LongMemEval/LoCoMo equivalents.
- Publishing v5. Owned by Phase 44 and requires explicit user OTP authorization.
- Enabling background dreaming. This remains intentionally disabled unless a later safety gate changes the decision.
