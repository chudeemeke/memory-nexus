# Phase 41.1: Embedding Pipeline Resilience Summary

**Provider-limit-aware embedding now survives oversized Ollama requests, records safe model-scoped skips, and continues later rows instead of wedging resume.**

## Performance

- **Duration:** Multi-session continuation
- **Started:** 2026-06-22T01:43:28+01:00
- **Completed:** 2026-06-22T03:07:50+01:00
- **Tasks:** 5/5
- **Files modified:** embedding domain/application/infrastructure/CLI, tests, planning, and dependency manifests

## Accomplishments

- Added `EmbeddingProviderError` with `payload_too_large` classification so the application layer can react without knowing Ollama or nginx details.
- Updated `OllamaEmbeddingProvider` to split multi-item HTTP 413 batches and preserve input/result order.
- Added `embedding_skips` persistence and repository filtering so current-model single-item failures do not block later rows and old-model skips do not hide retryable rows after model changes.
- Added `embedding.maxBatchBytes` config and service-side byte-bounded chunking.
- Updated `memory sync --embed` reporting to include handled skipped counts in text and JSON without exposing raw transcript content.
- Closed the dependency-audit release blocker by updating `@anthropic-ai/claude-code`, `vitest`, `vite`, and `protobufjs` resolution.

## Decisions Made

- The correct fix is provider-limit-aware memory behavior, not raising Tailscale/nginx limits as the primary solution.
- Skip/quarantine metadata stores provider/model/reason/hash/size style evidence only; raw message content is never logged or stored in skip diagnostics.
- `eval:v5` market ineligibility remains an honest future-phase blocker because two fixtures are still contract-only.
