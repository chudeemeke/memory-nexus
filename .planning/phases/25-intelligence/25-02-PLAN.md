**What:** Create `src/application/services/budget-allocator.ts` as a pure function with zero dependencies.

**Why:** The smart context service needs to distribute a token budget across prioritized sections. Extracting this as a pure function makes it trivially testable and reusable.

### RED: Write failing tests first

Create `src/application/services/budget-allocator.test.ts`:

1. **Basic allocation:**
   - 3 sections, budget fits all: all returned untruncated, `truncated: false`
   - 3 sections, budget fits first 2 only: third section truncated
   - 3 sections, budget fits none: all sections have `truncatedContent: ""` or partial content

2. **Priority ordering:**
   - Sections filled in priority order (priority 1 first, then 2, then 3)
   - Lower-priority sections are truncated/dropped before higher-priority ones
   - Sections with same priority: order preserved from input

3. **Edge cases:**
   - Budget 0: no constraint, all sections returned untruncated
   - Budget negative (-1): no constraint, all sections returned untruncated
   - Empty sections array: returns empty array
   - Single section: gets full budget
   - Section with empty content: skipped (0 allocation), `truncated: false`
   - Budget exactly equal to total content: all fit, none truncated

4. **Token estimation:**
   - Default charsPerToken is 4
   - Custom charsPerToken respected
   - `allocated` field reflects token count (characters / charsPerToken)
   - `totalTokensUsed` in return value is sum of all allocated tokens

5. **Truncation behavior:**
   - Truncated content is a prefix of the original (sliced at character boundary)
   - `truncatedContent` for fully excluded sections is `""`

```typescript
/**
 * Budget Allocator
 *
 * Pure function that distributes a token budget across prioritized sections.
 * Sections are filled in priority order (1 = highest). Lower-priority sections
 * are truncated first when budget is exceeded.
 *
 * Token estimation: ~4 characters per token for English text.
 */

export interface BudgetSection {
  /** Section identifier (e.g., "decisions", "learnings") */
  key: string;
  /** Priority (1 = highest, filled first) */
  priority: number;
  /** Section content text */
  content: string;
}

export interface AllocatedSection extends BudgetSection {
  /** Content after budget truncation (prefix of original) */
  truncatedContent: string;
  /** Estimated tokens allocated to this section */
  allocated: number;
  /** Whether this section was truncated */
  truncated: boolean;
}

export interface BudgetAllocationResult {
  sections: AllocatedSection[];
  totalTokensUsed: number;
  budgetExceeded: boolean;
}

export function allocateBudget(
  sections: BudgetSection[],
  totalBudget: number,
  charsPerToken = 4,
): BudgetAllocationResult {
  // No budget constraint: return all untruncated
  if (totalBudget <= 0) {
    const allocated = sections.map((s) => ({
      ...s,
      truncatedContent: s.content,
      allocated: Math.ceil(s.content.length / charsPerToken),
      truncated: false,
    }));
    const totalTokensUsed = allocated.reduce((sum, s) => sum + s.allocated, 0);
    return { sections: allocated, totalTokensUsed, budgetExceeded: false };
  }

  const charBudget = totalBudget * charsPerToken;
  const sorted = [...sections].sort((a, b) => a.priority - b.priority);
  let remaining = charBudget;
  const results: AllocatedSection[] = [];
  let budgetExceeded = false;

  for (const section of sorted) {
    if (section.content.length === 0) {
      results.push({
        ...section,
        truncatedContent: "",
        allocated: 0,
        truncated: false,
      });
      continue;
    }

    if (remaining <= 0) {
      results.push({
        ...section,
        truncatedContent: "",
        allocated: 0,
        truncated: true,
      });
      budgetExceeded = true;
      continue;
    }

    const charEstimate = section.content.length;
    if (charEstimate <= remaining) {
      const tokenEstimate = Math.ceil(charEstimate / charsPerToken);
      results.push({
        ...section,
        truncatedContent: section.content,
        allocated: tokenEstimate,
        truncated: false,
      });
      remaining -= charEstimate;
    } else {
      const truncated = section.content.slice(0, remaining);
      const tokenEstimate = Math.ceil(remaining / charsPerToken);
      results.push({
        ...section,
        truncatedContent: truncated,
        allocated: tokenEstimate,
        truncated: true,
      });
      remaining = 0;
      budgetExceeded = true;
    }
  }

  const totalTokensUsed = results.reduce((sum, s) => sum + s.allocated, 0);
  return { sections: results, totalTokensUsed, budgetExceeded };
}
```

## Task 2: Smart Context Service

**What:** Create `src/application/services/smart-context-service.ts` -- the application-layer service that composes memory files, friction entries, and session data into structured briefings.

**Why:** The current `SqliteContextService` (infrastructure) returns session metadata (counts, dates, tool usage). This is useless for understanding what happened or what to do next. The new SmartContextService reads agent-written memory files and produces actionable briefings within a token budget.

### RED: Write failing tests first

Create `src/application/services/smart-context-service.test.ts`:

All dependencies injected via constructor. Tests use mock implementations (no database):

1. **Project resolution:**
   - Resolves project name to encoded path via `IProjectResolver` dependency
   - Returns null result when project not found (no sessions matching the name)

2. **Data source assembly (priority order):**
   - Section 1: "Active Decisions" from project DECISIONS.md memory file (priority 1)
   - Section 2: "Recent Learnings" from project LEARNINGS.md memory file (priority 2)
   - Section 3: "Recent Activity" from daily log memory files filtered by `days` option (priority 3)
   - Section 4: "Cross-Project Decisions" from global DECISIONS.md -- only when `crossProject: true` (priority 4)
   - Section 5: "Cross-Project Learnings" from `findCrossProjectLearnings()` -- only when `crossProject: true` (priority 5)
   - Section 6: "Open Friction" from `IFrictionRepository.findOpen()` filtered by project if possible (priority 6)
   - Section 7: "Session Summary" from legacy `SqliteContextService.getProjectContext()` (priority 7, fallback)

3. **Budget integration:**
   - When `budget` option is set, passes assembled sections through `allocateBudget()`
   - When `budget` is undefined/0, all sections returned untruncated
   - `SmartContextResult.truncated` is true when any section was truncated

4. **Days filtering:**
   - Daily logs filtered to last N days when `days` option set
   - Default: no day limit (all daily logs included)

5. **Cross-project flag:**
   - `crossProject: false` (default): sections 4 and 5 omitted entirely
   - `crossProject: true`: sections 4 and 5 included

6. **Graceful degradation:**
   - No memory files for project: sections 1-3 empty, section 7 (session summary) becomes primary
   - No friction entries: section 6 empty, omitted from output
   - No daily logs: section 3 empty
   - All empty: result has empty sections array, `projectName` still set

7. **Friction formatting:**
   - Open friction entries formatted as `#id (severity/category): description`
   - Only includes entries where description or context mentions the project name (best-effort filter)
   - If no project-specific friction, includes all open friction (tool-level friction is always relevant)

**Implementation notes:**

1. `getContext(options)` orchestrates:
   - Resolve project name -> encoded path via `projectResolver`
   - If not found, return null
   - Query memory files by project encoded path: filter by type (decisions, learnings, daily_log)
   - Query friction entries via `frictionRepo.findOpen()`
   - Query cross-project learnings via `memoryFileRepo.findCrossProjectLearnings()` if `crossProject: true`
   - Build sections array with priorities 1-7
   - If `budget > 0`, pass through `allocateBudget()`
   - Return `SmartContextResult`

2. Memory file content extraction: the `content` field of `MemoryFile` entity contains the full markdown text. Use it directly as section content.

3. Daily log filtering by days: compare `MemoryFile.lastIndexedAt` (or parse date from the file path `daily/<YYYY-MM-DD>.md`) against the `days` window. Use file path date parsing since daily logs follow the naming convention `daily/<date>.md`.

4. Friction entry formatting: format each `FrictionEntry` as a single line: `#<id> (<severity>/<category>): <description>`. Join with newlines for the section content.

5. Session summary fallback: when no memory files exist, format a simple summary from session count + message count + last activity date. Do NOT inject the full legacy SqliteContextService -- instead accept a simpler `getSessionSummary(projectFilter: string, days?: number): string | null` function in deps, which the CLI command will wire to the existing infrastructure service. This avoids coupling the application service to infrastructure types.
