# Plan 25-04: Fix flaky vector-only temporal decay test

## Gap Being Closed

The test `HybridSearchService > uniform temporal decay > vector-only mode applies temporal decay` at line 1103 of `hybrid-search-service.test.ts` is non-deterministic. It inserts two messages with random embeddings (via `insertTestEmbedding`) and a query embedding (via `createMockProvider` which returns `createMockEmbeddingResult` with random values). When both stored embeddings are approximately orthogonal to the random query embedding, cosine similarity is near 0 for both. Multiplying near-zero scores by different decay factors still yields near-zero for both, making sort order indeterminate.

The decay implementation is correct (verified by FTS decay test, hybrid regression test, and code inspection). Only the test needs fixing.

## Approach

Spy on `mockProvider.embed` to return a **controlled** query embedding, and modify the test to insert stored embeddings with **controlled** values that **force decay to be the ordering factor**. This guarantees deterministic cosine similarity scores and proves decay actually changes the result.

The key insight: `msg-old` should have **higher** raw cosine similarity than `msg-new`, but its old timestamp causes decay to reduce its score below `msg-new`'s. Without decay, `msg-old` would rank first; with decay, `msg-new` ranks first. This proves decay is doing real work.

Specifically:
- Create a known unit vector as the query embedding: `[1, 0, 0, ..., 0]`
- Insert `msg-old` (60+ days ago) with an embedding that has **high** cosine similarity to the query. Use a vector like `[0.95, 0.31, 0, ..., 0]` (normalized, ~0.95 similarity). Without decay, this message would rank first.
- Insert `msg-new` (today) with an embedding that has **moderate** cosine similarity to the query. Use a vector like `[0.7, 0.71, 0, ..., 0]` (normalized, ~0.7 similarity). Without decay, this message would rank second.
- With decay applied: `msg-old`'s score becomes `~0.95 * ~0.25 (60-day decay) = ~0.24`. `msg-new`'s score becomes `~0.7 * ~1.0 (recent) = ~0.7`. Now `msg-new` ranks first.
- The assertion `expect(results[0].messageId).toBe("msg-new")` can ONLY pass if decay is applied and working correctly.

This approach does not require mocking `vectorKnnSearch` or changing any production code. It only changes how the test constructs embeddings.

- [ ] No other tests in hybrid-search-service.test.ts are broken by the change
- [ ] The test still validates that temporal decay affects vector-only search ordering (not a vacuous assertion)
