**A) SqliteProjectResolver** -- add to `src/infrastructure/database/services/context-service.ts`:

```typescript
import type { IProjectResolver } from "../../../application/services/smart-context-service.js";

export class SqliteProjectResolver implements IProjectResolver {
  private readonly db: Database;

  constructor(db: Database) {
    this.db = db;
  }

  resolveProjectEncoded(projectFilter: string): string | null {
    // Exact match first
    const exact = this.db
      .prepare<{ project_path_encoded: string }, [string]>(
        `SELECT DISTINCT project_path_encoded
         FROM sessions
         WHERE LOWER(project_name) = LOWER(?)
         LIMIT 1`
      )
      .get(projectFilter);
    if (exact) return exact.project_path_encoded;

    // Substring match ranked by session count
    const fuzzy = this.db
      .prepare<{ project_path_encoded: string }, [string]>(
        `SELECT project_path_encoded
         FROM sessions
         WHERE project_name LIKE '%' || ? || '%'
         GROUP BY project_path_encoded
         ORDER BY COUNT(*) DESC
         LIMIT 1`
      )
      .get(projectFilter);
    return fuzzy?.project_path_encoded ?? null;
  }

  resolveProjectName(projectFilter: string): string | null {
    const exact = this.db
      .prepare<{ project_name: string }, [string]>(
        `SELECT DISTINCT project_name
         FROM sessions
         WHERE LOWER(project_name) = LOWER(?)
         LIMIT 1`
      )
      .get(projectFilter);
    if (exact) return exact.project_name;

    const fuzzy = this.db
      .prepare<{ project_name: string }, [string]>(
        `SELECT project_name
         FROM sessions
         WHERE project_name LIKE '%' || ? || '%'
         GROUP BY project_name
         ORDER BY COUNT(*) DESC
         LIMIT 1`
      )
      .get(projectFilter);
    return fuzzy?.project_name ?? null;
  }
}
```

   ```typescript
   import { formatForAi } from "./ai-formatter.js";
   import type { SmartContextResult } from "../../../application/services/smart-context-service.js";

   class AiContextFormatter implements ContextFormatter {
     formatContext(context: ProjectContext, _options?: ContextFormatOptions): string {
       // Fallback: format legacy ProjectContext as clean text
       const brief = new BriefContextFormatter(false);
       return formatForAi(brief.formatContext(context, _options));
     }

     formatSmartContext(result: SmartContextResult): string {
       let output = `## ${result.projectName} context\n\n`;
       for (const section of result.sections) {
         if (section.content.trim() === "") continue;
         output += `### ${section.title}\n`;
         output += section.content;
         if (section.truncated) {
           output += "\n[truncated]";
         }
         output += "\n\n";
       }
       if (result.truncated) {
         output += `(budget: ~${result.totalTokensEstimate} tokens)\n`;
       }
       return output.trim();
     }

     formatError(error: Error): string {
       return `Error: ${error instanceof Error ? error.message : String(error)}`;
     }

     formatEmpty(projectName: string): string {
       return `No sessions found for project matching '${projectName}'`;
     }

     formatNoTopics(): string {
       return "No topics extracted yet";
     }
   }
   ```

## Task 3: --format ai on All Other Commands

**What:** Add `--format ai` option to search, list, show, stats, friction, and related commands. When set, output is piped through `formatForAi()` before printing.

**Why:** Claude (the primary consumer of this tool) wastes tokens on ANSI escape sequences and decorative box-drawing characters. `--format ai` strips these for clean, token-efficient output.

### RED: Write failing tests first

For each command (search, list, show, stats, friction, related), add one test:

1. Test: `--format ai` flag accepted without error
2. Test: output with `--format ai` contains no ANSI escape sequences (verify via regex `/\x1b\[/`)
3. Test: output content is preserved (only decoration stripped, not data)

### GREEN: Implement

The implementation approach per Research recommendation (verified from codebase analysis): add `--format` option individually to each command rather than root-level inheritance. This matches the existing pattern where each command manages its own options.

**Pattern for each command:**

For commands that already have a `--format` option (only `context`, already handled in Task 2):
- Add `"ai"` to existing choices

For commands that do NOT have a `--format` option (search, list, show, stats, friction, related):
- Add `--format <type>` option with choices `["default", "ai"]` and default `"default"`
- In the action handler, check `options.format === "ai"`
- If AI format: after formatting output with existing formatter, pipe through `formatForAi()` before `console.log()`

**Implementation per command:**

1. **search.ts**: Add `--format` option. When `ai`, pipe output through `formatForAi()` after existing formatter. Also handle `--json` as before (json takes precedence if both set).

2. **list.ts**: Add `--format` option. When `ai`, use `formatForAi()` wrapper.

3. **show.ts**: Add `--format` option. When `ai`, use `formatForAi()` wrapper.

4. **stats.ts**: Add `--format` option. When `ai`, use `formatForAi()` wrapper.

5. **friction.ts**: Add `--format` option to the parent `friction` command (Commander subcommand group). Each subcommand (log, list, resolve, dashboard) inherits from parent. When `ai`, the dashboard subcommand renders stats only (no charts), and list/log/resolve output is stripped of ANSI.

6. **related.ts**: Add `--format` option. When `ai`, use `formatForAi()` wrapper.

**Key implementation detail:** The `formatForAi()` wrapper approach is intentionally simple. Rather than creating parallel AI formatter classes for each command (12+ new classes), we wrap the existing formatter output through `formatForAi()`. This strips ANSI codes and normalizes whitespace. The content is already well-structured (tables, headers, bullet points) -- we just remove the terminal decoration.

For friction dashboard specifically: when `--format ai` is set, skip the Chart.js HTML generation path and only render the stats portion (text-only). This requires checking the format option inside the dashboard action handler.
