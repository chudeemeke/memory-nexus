# Plan 15-02: Sync Command --embed Integration with Progress and Model Change Handling

## Goal

Wire the `EmbeddingService` (from Plan 15-01) into the sync command via `--embed` flag. When `--embed` is present, the sync command performs extraction as usual, then runs a second embedding pass for all unembedded messages. The embedding pass has its own progress bar (separate from the sync progress bar), handles first-run model download with a dedicated progress indicator, prints a completion summary, and prompts for confirmation on model change. Without `--embed`, the sync command behaves identically to v1.0.

## must_haves

- [ ] `memory sync --embed` extracts sessions AND generates embeddings for unembedded messages after extraction completes
- [ ] `memory sync` (without `--embed`) does NOT load the ONNX runtime, import the embedding provider, or create the EmbeddingService -- zero overhead on the non-embedding path
- [ ] Embedding progress bar shows `"Embedding |{bar}| {percentage}% | {value}/{total} messages | ETA: {eta_formatted}"` in TTY mode
- [ ] First-run model download shows its own progress indicator BEFORE the embedding progress bar starts (via provider's `initialize(onProgress)` callback)
- [ ] Completion summary prints `"Embedded N messages in Xs (Y.Z msg/s)"` matching the existing sync summary style
- [ ] On embedding failure partway through: prints `"Embedding failed at M/N messages. Run memory sync --embed to resume from where it stopped."` and exits with code 1 but does NOT lose extracted sync data or already-embedded messages
- [ ] On model change detection: prompts `"Model changed from X to Y. Re-embed all N messages? [y/N]"` where X and Y are **human-readable model names** (e.g., "Xenova/all-MiniLM-L6-v2"), NOT opaque hex hashes -- default No
- [ ] `--force` flag bypasses model change confirmation (auto-confirms re-embedding)
- [ ] In non-interactive mode (no TTY, `--quiet`, or `--non-interactive` implied by CI/hooks): skips re-embedding with a warning to stderr showing human-readable model names
- [ ] `--embed` flag is listed in `memory sync --help` output
- [ ] 95%+ coverage at EACH metric for all new and modified files

```typescript
/**
 * Interface for reporting embedding progress.
 */
export interface EmbeddingProgressReporter {
  start(total: number): void;
  update(current: number): void;
  stop(): void;
}

export class TtyEmbeddingProgressReporter implements EmbeddingProgressReporter {
  private bar: cliProgress.SingleBar;

  constructor() {
    this.bar = new cliProgress.SingleBar({
      format: "Embedding |{bar}| {percentage}% | {value}/{total} messages | ETA: {eta_formatted}",
      barCompleteChar: "\u2588",
      barIncompleteChar: "\u2591",
      hideCursor: true,
      etaBuffer: 20,
    });
  }

  start(total: number): void { this.bar.start(total, 0); }
  update(current: number): void { this.bar.update(current); }
  stop(): void { this.bar.stop(); }
}

export class PlainEmbeddingProgressReporter implements EmbeddingProgressReporter {
  start(total: number): void { console.log(`Embedding ${total} messages...`); }
  update(_current: number): void { /* batch updates not shown in plain mode */ }
  stop(): void { console.log("Done."); }
}

export class QuietEmbeddingProgressReporter implements EmbeddingProgressReporter {
  start(_total: number): void {}
  update(_current: number): void {}
  stop(): void {}
}

export function createEmbeddingProgressReporter(options: {
  quiet?: boolean;
}): EmbeddingProgressReporter {
  if (options.quiet) return new QuietEmbeddingProgressReporter();
  if (!process.stdout.isTTY) return new PlainEmbeddingProgressReporter();
  return new TtyEmbeddingProgressReporter();
}
```

Also add a helper for model download progress. The provider's `initialize(onProgress)` calls back with `DownloadProgress` objects. On TTY, this should show a download progress bar. On non-TTY/quiet, suppress or show minimal text.

```typescript
import type { DownloadProgress } from "../../domain/ports/embedding.js";

export function createModelDownloadHandler(options: {
  quiet?: boolean;
}): (progress: DownloadProgress) => void {
  if (options.quiet || !process.stdout.isTTY) {
    // Non-TTY: show a single line when download starts
    let announced = false;
    return (progress: DownloadProgress) => {
      if (!announced && progress.status === "downloading" && !options.quiet) {
        console.log("Downloading embedding model (one-time setup)...");
        announced = true;
      }
    };
  }

  // TTY: show animated progress bar for download
  const downloadBar = new cliProgress.SingleBar({
    format: "Downloading model |{bar}| {percentage}% | {value}/{total} MB",
    barCompleteChar: "\u2588",
    barIncompleteChar: "\u2591",
    hideCursor: true,
  });
  let started = false;

  return (progress: DownloadProgress) => {
    if (progress.status === "downloading") {
      const loadedMb = Math.round(progress.loaded / 1048576);
      const totalMb = Math.round(progress.total / 1048576);
      if (!started) {
        downloadBar.start(totalMb, loadedMb);
        started = true;
      } else {
        downloadBar.update(loadedMb);
      }
    } else if (progress.status === "ready" && started) {
      downloadBar.stop();
    }
  };
}
```

<task id="15-02-B" title="Sync command --embed flag with embedding pass orchestration (TDD)">

### Context

The sync command in `sync.ts` follows this flow: parse options -> initialize DB -> create repositories -> create SyncService -> execute sync -> checkpoint WAL -> report results -> cleanup. The `--embed` flag adds a second phase after the sync completes.

**Locked decisions:**
- Embedding is a second pass AFTER extraction completes
- Embedding runs in a SEPARATE database transaction from sync extraction
- `--embed` processes ALL unembedded messages (not just current sync run)
- On failure: extracted sync data is safe, already-embedded messages are kept
- Model change confirmation prompt: `"Model changed from X to Y. Re-embed all N messages? [y/N]"` where **X and Y are human-readable model names** from `ModelState.storedModelName` and `ModelState.currentModelName` (per locked CONTEXT.md decision)
- Non-interactive (no TTY, hooks, `--force`): skip re-embedding with warning, or auto-re-embed with `--force`

The sync command currently defines `SyncCommandOptions`. Add `embed?: boolean` to this interface.

**Critical:** When `--embed` is NOT specified, the sync command must NOT import or instantiate anything from the embedding infrastructure. Use dynamic import (`import()`) to lazy-load the embedding modules only when `--embed` is true. This ensures `memory sync` without `--embed` never touches ONNX.

4. Implement `runEmbeddingPass()` as a separate function within sync.ts:

```typescript
async function runEmbeddingPass(
  db: ReturnType<typeof initializeDatabase>["db"],
  options: SyncCommandOptions
): Promise<void> {
  // Lazy import to avoid loading ONNX when --embed is not used
  const { EmbeddingService, computeModelHash } = await import(
    "../../../application/services/embedding-service.js"
  );
  const { EmbeddingRepository } = await import(
    "../../../infrastructure/database/repositories/embedding-repository.js"
  );
  const { EmbeddingProviderFactory } = await import(
    "../../../infrastructure/embedding/embedding-provider-factory.js"
  );
  const { loadConfig } = await import(
    "../../../infrastructure/hooks/config-manager.js"
  );
  const { createEmbeddingProgressReporter, createModelDownloadHandler } = await import(
    "../progress-reporter.js"
  );

  const config = loadConfig();
  const factory = new EmbeddingProviderFactory();
  const provider = factory.createFromConfig(config);

  if (!provider) {
    if (!options.quiet) {
      console.error("Embedding is disabled in configuration. Enable it in ~/.config/memory/config.json");
    }
    return;
  }

  const repository = new EmbeddingRepository(db);
  const service = new EmbeddingService({
    repository,
    provider,
    config: config.embedding,
  });

  // Check for model change
  const modelState = service.checkModelState();
  if (modelState.modelChanged && modelState.needsReEmbed) {
    const proceed = await handleModelChange(modelState, options);
    if (!proceed) {
      await factory.dispose();
      return;
    }
    // User confirmed re-embedding
    if (!options.quiet) {
      console.log("Clearing existing embeddings for re-embedding...");
    }
  }

  // Initialize provider (triggers model download on first run)
  const downloadHandler = createModelDownloadHandler({ quiet: options.quiet });
  await provider.initialize(downloadHandler);

  // Run embedding pass
  const embeddingReporter = createEmbeddingProgressReporter({ quiet: options.quiet });
  const totalToEmbed = repository.getTotalMessageCount() - repository.getEmbeddedCount();

  if (totalToEmbed === 0) {
    if (!options.quiet) {
      console.log("\nAll messages already embedded.");
    }
    await factory.dispose();
    return;
  }

  embeddingReporter.start(totalToEmbed);

  try {
    let result;
    if (modelState.modelChanged && modelState.needsReEmbed) {
      result = await service.clearAndReembed({
        onProgress: (p) => embeddingReporter.update(p.current),
      });
    } else {
      result = await service.embedUnembedded({
        onProgress: (p) => embeddingReporter.update(p.current),
      });
    }

    embeddingReporter.stop();

    if (!options.quiet) {
      const seconds = (result.durationMs / 1000).toFixed(0);
      const rate = result.rate.toFixed(1);
      console.log(`\nEmbedded ${result.embedded} messages in ${seconds}s (${rate} msg/s)`);
    }
  } catch (error) {
    embeddingReporter.stop();
    const embeddedSoFar = repository.getEmbeddedCount();
    const total = repository.getTotalMessageCount();
    if (!options.quiet) {
      console.error(
        `\nEmbedding failed at ${embeddedSoFar}/${total} messages. ` +
        `Run memory sync --embed to resume from where it stopped.`
      );
    }
    // Re-throw so executeSyncCommand returns exit code 1
    throw error;
  } finally {
    await factory.dispose();
  }
}
```

5. Implement `handleModelChange()` using **human-readable model names** from `ModelState.storedModelName` and `ModelState.currentModelName`:

```typescript
import * as readline from "node:readline";

async function handleModelChange(
  modelState: ModelState,
  options: SyncCommandOptions
): Promise<boolean> {
  const count = modelState.embeddedCount ?? 0;
  // Use human-readable model names per locked CONTEXT.md decision
  const fromModel = modelState.storedModelName ?? modelState.storedHash ?? "unknown";
  const toModel = modelState.currentModelName;

  // --force: auto-confirm
  if (options.force) {
    return true;
  }

  // Non-interactive: skip with warning
  if (!process.stdin.isTTY || options.quiet) {
    console.error(
      `Model changed from ${fromModel} to ${toModel}. ` +
      `Skipping re-embedding in non-interactive mode. ` +
      `Run 'memory sync --embed' interactively to re-embed.`
    );
    return false;
  }

  // Interactive prompt
  const rl = readline.createInterface({ input: process.stdin, output: process.stdout });
  return new Promise((resolve) => {
    rl.question(
      `Model changed from ${fromModel} to ${toModel}. ` +
      `Re-embed all ${count} messages? [y/N] `,
      (answer) => {
        rl.close();
        resolve(answer.trim().toLowerCase() === "y");
      }
    );
  });
}
```
