# Plan 15-01: EmbeddingRepository and EmbeddingService with Model Hash Tracking

## Goal

Build the data access layer for embedding storage (embedding_state + message_embeddings tables) and the application service that orchestrates the embedding pipeline: querying unembedded messages, batching them through a provider, storing results, tracking model hashes for change detection, and handling re-embedding. These are the core building blocks that the sync command (Plan 15-02) and background embedding (Plan 15-03) will consume.

## must_haves

- [ ] `EmbeddingRepository` exists in `src/infrastructure/database/repositories/embedding-repository.ts` with methods: `findUnembedded(limit)`, `storeBatch(items, modelHash, modelName)`, `getStoredModelHash()`, `getStoredModelName()`, `clearAllEmbeddings()`, `getEmbeddedCount()`, `getTotalMessageCount()`
- [ ] `findUnembedded(limit)` returns `Array<{ rowid: number; content: string }>` using LEFT JOIN on `messages_meta` and `embedding_state`
- [ ] `storeBatch()` inserts into both `message_embeddings` (vec0 via `vec_f32()`) and `embedding_state` within a single transaction, storing both `model_hash` and `model_name`
- [ ] `getStoredModelHash()` returns the current model_hash from `embedding_state`, or null if no embeddings exist
- [ ] `getStoredModelName()` returns the current model_name from `embedding_state`, or null if no embeddings exist
- [ ] `clearAllEmbeddings()` deletes all rows from `message_embeddings` and `embedding_state` (for re-embedding)
- [ ] `computeModelHash(config)` generates a SHA-256 based hash from `provider:model:dimensions` string (truncated to 16 hex chars)
- [ ] `EmbeddingService` exists in `src/application/services/embedding-service.ts` orchestrating: check model hash -> query unembedded -> batch embed -> store results -> return summary
- [ ] `EmbeddingService.embedUnembedded(options)` returns `EmbedResult` with `{ embedded: number, skipped: number, durationMs: number, rate: number }`
- [ ] `EmbeddingService` detects model change via `getStoredModelHash()` comparison and returns `ModelState` with `storedModelName` and `currentModelName` (human-readable model names) for use in confirmation prompts
- [ ] `EmbeddingService` calls `onProgress` callback after each batch for progress reporting
- [ ] `EmbeddingConfigData` interface extended with optional `batchSize` field (default: 100)
- [ ] `DEFAULT_EMBEDDING_CONFIG` updated to include `batchSize: 100`
- [ ] `embedding_state` schema extended with `model_name TEXT NOT NULL DEFAULT ''` column via ALTER TABLE migration
- [ ] 95%+ coverage at EACH metric for all new and modified files

## Tasks

<task id="15-01-A" title="EmbeddingRepository -- database CRUD for embeddings (TDD)">

### Context

The existing repository pattern uses class constructors that accept a `Database` instance from `bun:sqlite`. See `SqliteSessionRepository`, `SqliteMessageRepository` for the pattern. Each repository exposes typed methods with prepared statements for performance.

The `embedding_state` table has columns: `message_id INTEGER PRIMARY KEY`, `embedded_at TEXT NOT NULL`, `model_hash TEXT NOT NULL` with FK to `messages_meta(rowid)`.

**Schema extension:** The `embedding_state` table needs a `model_name TEXT NOT NULL DEFAULT ''` column to store the human-readable model name (e.g., "Xenova/all-MiniLM-L6-v2") alongside the hash. This is required because the locked decision specifies the model change prompt as "Model changed from X to Y" where X and Y are human-readable model names, not opaque hex hashes. The column is added via ALTER TABLE (since the table was created in Phase 14). Add the ALTER TABLE statement to `schema.ts` as a migration constant and execute it in the repository constructor or via `initializeDatabase()`.

The `message_embeddings` table is a `vec0` virtual table with `embedding float[384]`. Inserts use `vec_f32()` to convert Float32Array to the vec0 storage format: `INSERT INTO message_embeddings(rowid, embedding) VALUES (?, vec_f32(?))`.

**Critical pitfall (from research):** The `message_embeddings` rowid must match `messages_meta.rowid` (integer), NOT the message UUID string `id`. Always use `m.rowid` when querying messages for embedding.

**Open question (from research):** Whether bun:sqlite passes Float32Array correctly to sqlite-vec's `vec_f32()` function. The first storeBatch test will validate this. If Float32Array does not work, convert to Buffer: `Buffer.from(embedding.buffer)`.

Create `src/infrastructure/database/repositories/embedding-repository.ts`:

```typescript
import type { Database } from "bun:sqlite";

export interface UnembeddedMessage {
  rowid: number;
  content: string;
}

export interface EmbeddingBatchItem {
  rowid: number;
  embedding: Float32Array;
}

export class EmbeddingRepository {
  constructor(private readonly db: Database) {}

  findUnembedded(limit: number): UnembeddedMessage[] {
    return this.db.prepare<UnembeddedMessage, [number]>(`
      SELECT m.rowid, m.content
      FROM messages_meta m
      LEFT JOIN embedding_state es ON m.rowid = es.message_id
      WHERE es.message_id IS NULL
      ORDER BY m.rowid ASC
      LIMIT ?
    `).all(limit);
  }

  storeBatch(items: EmbeddingBatchItem[], modelHash: string, modelName: string): void {
    const insertVec = this.db.prepare(
      "INSERT INTO message_embeddings(rowid, embedding) VALUES (?, vec_f32(?))"
    );
    const insertState = this.db.prepare(
      "INSERT INTO embedding_state(message_id, embedded_at, model_hash, model_name) VALUES (?, ?, ?, ?)"
    );
    const txn = this.db.transaction((batch: EmbeddingBatchItem[]) => {
      const now = new Date().toISOString();
      for (const item of batch) {
        insertVec.run(item.rowid, item.embedding);
        insertState.run(item.rowid, now, modelHash, modelName);
      }
    });
    txn(items);
  }

  getStoredModelHash(): string | null {
    const row = this.db.prepare<{ model_hash: string }, []>(
      "SELECT DISTINCT model_hash FROM embedding_state LIMIT 1"
    ).get();
    return row?.model_hash ?? null;
  }

  getStoredModelName(): string | null {
    const row = this.db.prepare<{ model_name: string }, []>(
      "SELECT DISTINCT model_name FROM embedding_state WHERE model_name != '' LIMIT 1"
    ).get();
    return row?.model_name ?? null;
  }

  clearAllEmbeddings(): void {
    this.db.exec("DELETE FROM message_embeddings");
    this.db.exec("DELETE FROM embedding_state");
  }

  getEmbeddedCount(): number {
    const row = this.db.prepare<{ count: number }, []>(
      "SELECT COUNT(*) as count FROM embedding_state"
    ).get();
    return row?.count ?? 0;
  }

  getTotalMessageCount(): number {
    const row = this.db.prepare<{ count: number }, []>(
      "SELECT COUNT(*) as count FROM messages_meta"
    ).get();
    return row?.count ?? 0;
  }
}
```

<task id="15-01-B" title="EmbeddingService -- application layer embedding orchestrator (TDD)">

### Context

The `EmbeddingService` is an application layer service that orchestrates the embedding pipeline. It sits between the presentation layer (sync command) and infrastructure (repository + provider). It does NOT own the `IEmbeddingProvider` lifecycle -- the caller creates and initializes the provider, then passes it in.

**Locked decisions from CONTEXT.md:**
- Embedding is a second pass AFTER extraction -- EmbeddingService is called separately, not inside SyncService
- `--embed` processes ALL unembedded messages, not just current sync run
- Embedding runs in a SEPARATE database transaction from sync extraction
- On failure partway through: already-embedded messages are kept (each batch is its own transaction)
- Model change detection via hash comparison against `embedding_state.model_hash`
- Re-embedding is all-or-nothing: clear old embeddings then re-embed everything
- **Model change prompt must show human-readable model names** (e.g., "Xenova/all-MiniLM-L6-v2"), not opaque hex hashes. `ModelState` carries both `storedModelName` and `currentModelName` for this purpose.

The service needs access to:
- `EmbeddingRepository` (from Task 15-01-A)
- `IEmbeddingProvider` (domain port, already exists from Phase 14)
- `EmbeddingConfigData` for batch size and model hash computation

Also extend `EmbeddingConfigData` to include `batchSize`.

```typescript
import { createHash } from "node:crypto";
import type { IEmbeddingProvider } from "../../domain/ports/embedding.js";
import type { EmbeddingRepository, EmbeddingBatchItem } from "../../infrastructure/database/repositories/embedding-repository.js";
import type { EmbeddingConfigData } from "../../infrastructure/hooks/config-manager.js";

export interface EmbedOptions {
  onProgress?: (progress: EmbedProgress) => void;
}

export interface EmbedProgress {
  current: number;
  total: number;
}

export interface EmbedResult {
  embedded: number;
  skipped: number;
  durationMs: number;
  rate: number;
}

export interface ModelState {
  modelChanged: boolean;
  needsReEmbed: boolean;
  storedHash?: string;
  currentHash: string;
  /** Human-readable name of the previously-used model (from embedding_state.model_name).
   *  Falls back to storedHash if the stored name is unavailable (legacy data). */
  storedModelName?: string;
  /** Human-readable name of the currently-configured model (from config.model). */
  currentModelName: string;
  embeddedCount?: number;
}

export function computeModelHash(config: Pick<EmbeddingConfigData, "provider" | "model" | "dimensions">): string {
  const input = `${config.provider}:${config.model}:${config.dimensions}`;
  return createHash("sha256").update(input).digest("hex").slice(0, 16);
}

export class EmbeddingService {
  private readonly repository: EmbeddingRepository;
  private readonly provider: IEmbeddingProvider;
  private readonly batchSize: number;
  private readonly modelHash: string;
  private readonly modelName: string;

  constructor(deps: {
    repository: EmbeddingRepository;
    provider: IEmbeddingProvider;
    config: EmbeddingConfigData;
  }) {
    this.repository = deps.repository;
    this.provider = deps.provider;
    this.batchSize = deps.config.batchSize;
    this.modelHash = computeModelHash(deps.config);
    this.modelName = deps.config.model;
  }

  checkModelState(): ModelState {
    const storedHash = this.repository.getStoredModelHash();
    const currentHash = this.modelHash;
    const currentModelName = this.modelName;

    if (storedHash === null) {
      return { modelChanged: false, needsReEmbed: false, currentHash, currentModelName };
    }

    if (storedHash === currentHash) {
      return { modelChanged: false, needsReEmbed: false, currentHash, currentModelName };
    }

    // Model changed -- retrieve stored model name for human-readable prompt
    const storedModelName = this.repository.getStoredModelName() ?? storedHash;

    return {
      modelChanged: true,
      needsReEmbed: true,
      storedHash,
      currentHash,
      storedModelName,
      currentModelName,
      embeddedCount: this.repository.getEmbeddedCount(),
    };
  }

  async embedUnembedded(options: EmbedOptions = {}): Promise<EmbedResult> {
    const startTime = Date.now();
    let embedded = 0;

    // Get total count of unembedded messages for progress
    const totalUnembedded = this.repository.getTotalMessageCount() - this.repository.getEmbeddedCount();

    if (totalUnembedded <= 0) {
      return { embedded: 0, skipped: 0, durationMs: 0, rate: 0 };
    }

    // Process in batches
    let batch = this.repository.findUnembedded(this.batchSize);
    while (batch.length > 0) {
      // Embed the batch
      const texts = batch.map(m => m.content);
      const results = await this.provider.embedBatch(texts);

      // Store results with both hash and human-readable model name
      const items: EmbeddingBatchItem[] = batch.map((msg, i) => ({
        rowid: msg.rowid,
        embedding: results[i].embedding,
      }));
      this.repository.storeBatch(items, this.modelHash, this.modelName);

      embedded += batch.length;
      options.onProgress?.({ current: embedded, total: totalUnembedded });

      // Get next batch
      batch = this.repository.findUnembedded(this.batchSize);
    }

    const durationMs = Date.now() - startTime;
    const rate = durationMs > 0 ? (embedded / (durationMs / 1000)) : 0;

    return { embedded, skipped: 0, durationMs, rate };
  }

  async clearAndReembed(options: EmbedOptions = {}): Promise<EmbedResult> {
    this.repository.clearAllEmbeddings();
    return this.embedUnembedded(options);
  }
}
```
