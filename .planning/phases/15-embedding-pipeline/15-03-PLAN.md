# Plan 15-03: Background Embedding with PID Lock and Status Command Extension

## Goal

Implement the `--background` flag for `memory sync --embed` that spawns a detached child process to generate embeddings asynchronously, returning control to the user immediately. A PID lock file prevents concurrent embedding runs. The `memory status` command is extended to show background embedding progress when active. Background completion is silent (log entry only, no notification).

## must_haves

- [ ] `memory sync --embed --background` spawns a detached child process running `memory sync --embed --quiet`, writes a PID lock file, and returns immediately with a message like `"Background embedding started (PID 12345). Use 'memory status' to check progress."`
- [ ] PID lock file at `{dataDir}/embedding.lock` contains JSON: `{ pid, startedAt, totalMessages }` -- prevents double-run
- [ ] When lock file exists and PID is still alive: prints `"Embedding already in progress (PID 12345). Use 'memory status' to check progress."` and exits with code 0
- [ ] When lock file exists but PID is dead (stale lock): deletes stale lock and proceeds with new background process
- [ ] Background process cleans up the PID lock file on completion (both success and failure)
- [ ] `memory status` shows embedding section with live progress from database: `"Embedding: active (PID 12345, 150/500 messages, started 5 min ago)"` or `"Embedding: idle"` when no background process is running
- [ ] Background mode implies non-interactive: model change detection skips re-embedding with a warning logged to sync.log (not prompted)
- [ ] `--background` without `--embed` is a no-op with a hint: `"--background requires --embed flag"`
- [ ] 95%+ coverage at EACH metric for all new and modified files

<task id="15-03-A" title="Background embedder with PID lock lifecycle (TDD)">

### Context

The existing `spawnBackgroundSync()` in `hook-runner.ts` spawns a detached child process with:
- `spawn(command, args, { detached: true, stdio: ["ignore", out, err] })`
- `subprocess.unref()` to allow parent to exit
- Output redirected to sync.log

This task creates a `BackgroundEmbedder` module that reuses the same pattern but adds PID lock file management. The lock file serves two purposes: (1) prevent concurrent embedding runs, (2) provide status information for `memory status`.

**Locked decisions from CONTEXT.md:**
- `memory sync --embed --background` spawns a detached child process (reuse existing spawnBackgroundSync pattern)
- `memory status` shows background embedding progress (PID, message count)
- PID lock file in data dir prevents double-run
- Background completion: silent exit, log entry written to existing sync log

**Pitfall from research:** Background embedding process must detect that it IS the background process (not spawn another). Use an environment variable `MEMORY_EMBED_BACKGROUND=1` to signal this. The foreground sync command checks this env var and does NOT re-spawn when already in background mode.

**Pitfall from research:** Background + model change prompt conflict. Background mode has no TTY, so model change detection must skip re-embedding with a warning logged. The `--quiet` flag on the spawned command handles most of this, but model change logic in `runEmbeddingPass()` must also check for background mode.

### Green Phase -- Implement

Create `src/infrastructure/embedding/background-embedder.ts`:

```typescript
import { spawn } from "node:child_process";
import {
  existsSync,
  readFileSync,
  writeFileSync,
  unlinkSync,
  mkdirSync,
  openSync,
} from "node:fs";
import { join } from "node:path";
import { getDataDir, getLogDir } from "../paths.js";

export interface LockData {
  pid: number;
  startedAt: string;
  totalMessages: number;
}

export interface AcquireResult {
  acquired: boolean;
  staleRemoved?: boolean;
  existingPid?: number;
  startedAt?: string;
}

export interface SpawnResult {
  started: boolean;
  pid?: number;
  reason?: "already_running" | "spawn_failed";
}

function getLockPath(dataDir?: string): string {
  return join(dataDir ?? getDataDir(), "embedding.lock");
}

export function writeLock(data: LockData, dataDir?: string): void {
  const lockPath = getLockPath(dataDir);
  const dir = join(dataDir ?? getDataDir());
  mkdirSync(dir, { recursive: true });
  writeFileSync(lockPath, JSON.stringify(data));
}

export function readLock(dataDir?: string): LockData | null {
  const lockPath = getLockPath(dataDir);
  if (!existsSync(lockPath)) return null;
  try {
    return JSON.parse(readFileSync(lockPath, "utf-8")) as LockData;
  } catch {
    return null;
  }
}

export function removeLock(dataDir?: string): void {
  const lockPath = getLockPath(dataDir);
  try {
    unlinkSync(lockPath);
  } catch {
    // Lock file already gone or never existed -- fine
  }
}

export function isProcessAlive(pid: number): boolean {
  try {
    process.kill(pid, 0);
    return true;
  } catch {
    return false;
  }
}

export function acquireLock(
  pid: number,
  totalMessages: number,
  dataDir?: string
): AcquireResult {
  const existing = readLock(dataDir);

  if (existing) {
    if (isProcessAlive(existing.pid)) {
      return {
        acquired: false,
        existingPid: existing.pid,
        startedAt: existing.startedAt,
      };
    }
    // Stale lock -- remove it
    removeLock(dataDir);
  }

  writeLock(
    { pid, startedAt: new Date().toISOString(), totalMessages },
    dataDir
  );

  return {
    acquired: true,
    staleRemoved: existing !== null,
  };
}

export function spawnBackgroundEmbedding(options?: {
  dataDir?: string;
  logDir?: string;
  command?: string;
}): SpawnResult {
  const {
    dataDir,
    logDir: logDirOverride,
    command = process.execPath,
  } = options ?? {};
  const logDirPath = logDirOverride ?? getLogDir();
  mkdirSync(logDirPath, { recursive: true });

  const logPath = join(logDirPath, "sync.log");
  const out = openSync(logPath, "a");
  const err = openSync(logPath, "a");

  // Build args: re-invoke the memory CLI with --embed --quiet
  // Use process.argv[1] to find the memory CLI entry point
  const entryPoint = process.argv[1];
  const args = [entryPoint, "sync", "--embed", "--quiet"];

  const subprocess = spawn(command, args, {
    detached: true,
    stdio: ["ignore", out, err],
    env: {
      ...process.env,
      MEMORY_EMBED_BACKGROUND: "1",
    },
  });
  subprocess.unref();

  if (subprocess.pid === undefined) {
    return { started: false, reason: "spawn_failed" };
  }

  // Write lock file
  // totalMessages is 0 here -- the status command queries the database
  // directly for live progress counts (see 15-03-B gatherStatus)
  const lockResult = acquireLock(subprocess.pid, 0, dataDir);
  if (!lockResult.acquired) {
    // Should not happen since we just spawned, but handle gracefully
    return {
      started: false,
      reason: "already_running",
      pid: lockResult.existingPid,
    };
  }

  return { started: true, pid: subprocess.pid };
}

/**
 * Check if the current process is a background embedding process.
 * Set by spawnBackgroundEmbedding via MEMORY_EMBED_BACKGROUND=1.
 */
export function isBackgroundEmbedding(): boolean {
  return process.env.MEMORY_EMBED_BACKGROUND === "1";
}
```

6. The background process itself runs `memory sync --embed --quiet` with `MEMORY_EMBED_BACKGROUND=1`

The background process detects itself via `MEMORY_EMBED_BACKGROUND=1` and:
- Does NOT spawn another background process (avoids infinite recursion)

```typescript
async function handleBackgroundMode(
  options: SyncCommandOptions
): Promise<CommandResult> {
  const { spawnBackgroundEmbedding, readLock, isProcessAlive } = await import(
    "../../../infrastructure/embedding/background-embedder.js"
  );

  // Check existing lock
  const existingLock = readLock();
  if (existingLock && isProcessAlive(existingLock.pid)) {
    console.log(
      `Embedding already in progress (PID ${existingLock.pid}). ` +
      `Use 'memory status' to check progress.`
    );
    return { exitCode: 0 };
  }

  // Spawn background process
  const result = spawnBackgroundEmbedding();

  if (result.started) {
    console.log(
      `Background embedding started (PID ${result.pid}). ` +
      `Use 'memory status' to check progress.`
    );
  } else {
    console.error(`Failed to start background embedding: ${result.reason}`);
    return { exitCode: 1 };
  }

  return { exitCode: 0 };
}
```

```typescript
function formatTimeAgo(isoTimestamp: string): string {
  const diff = Date.now() - new Date(isoTimestamp).getTime();
  const minutes = Math.floor(diff / 60000);
  if (minutes < 1) return "just now";
  if (minutes < 60) return `${minutes} min ago`;
  const hours = Math.floor(minutes / 60);
  if (hours < 24) return `${hours}h ago`;
  return `${Math.floor(hours / 24)}d ago`;
}
```
