# Plan 23-02: FTS5 Query Sanitizer and Search Service Integration

## Goal

Create a pure `sanitizeFtsQuery()` function in the application layer that strips FTS5 operator characters from user queries, and integrate it into `Fts5SearchService.search()` so queries like "SYNC-09" and "Opus 4.6" no longer cause FTS5 syntax errors. Since `HybridSearchService` delegates FTS to `Fts5SearchService`, this fix propagates to hybrid search automatically. Also apply the sanitizer to `SessionRepository.searchSummaries()` for summary-based FTS5 queries via `sessions_fts`.

## must_haves

- [ ] `sanitizeFtsQuery()` function exists in `src/application/services/fts-sanitizer.ts`
- [ ] Periods, hyphens, colons, parentheses, brackets, braces, carets, asterisks, double quotes, and tildes are replaced with spaces
- [ ] Multiple consecutive spaces are collapsed to single space
- [ ] FTS5 keyword operators (AND, OR, NOT) are preserved (they are uppercase words, not special chars)
- [ ] Empty/whitespace-only queries after sanitization return a sensible fallback (alphanumeric parts joined)
- [ ] `Fts5SearchService.search()` applies `sanitizeFtsQuery()` before passing query to FTS5 MATCH
- [ ] `SessionRepository.searchSummaries()` applies `sanitizeFtsQuery()` before passing query to `sessions_fts` MATCH
- [ ] `memory search "SYNC-09"` returns results instead of FTS5 syntax error
- [ ] `memory search "Opus 4.6"` returns results instead of FTS5 syntax error
- [ ] All existing search tests pass with no behavioral regression
- [ ] All tests pass with 95%+ coverage at EACH metric for new files

## Tasks

<task id="23-02-A" title="sanitizeFtsQuery pure function (TDD)">

### Context

FTS5 treats certain characters as query operators. The `porter unicode61` tokenizer strips these during indexing, but user queries arrive raw and cause syntax errors when they contain periods (e.g., "4.6"), hyphens (e.g., "SYNC-09"), colons, parentheses, or brackets.

This is a pure function with zero dependencies -- it lives in the application layer as a utility, not in infrastructure.

### Green Phase -- Implement

Create `src/application/services/fts-sanitizer.ts`:

```typescript
/**
 * FTS5 Query Sanitizer
 *
 * Strips characters that FTS5 treats as syntax operators from user queries
 * before passing to MATCH. The porter unicode61 tokenizer strips these during
 * indexing, so queries need the same treatment for consistent matching.
 *
 * Preserves FTS5 keyword operators (AND, OR, NOT, NEAR) since they are
 * uppercase words, not special characters.
 */

/**
 * Sanitize a user query for safe use in FTS5 MATCH expressions.
 *
 * Replaces FTS5 operator characters with spaces and collapses whitespace.
 * If the result is empty after sanitization, falls back to extracting
 * alphanumeric parts from the original query.
 *
 * @param query Raw user query string
 * @returns Sanitized query safe for FTS5 MATCH
 */
export function sanitizeFtsQuery(query: string): string {
  const sanitized = query
    .replace(/[.:\-()[\]{}^*"~@/\\]/g, " ")
    .replace(/\s+/g, " ")
    .trim();

  if (sanitized) return sanitized;

  // Fallback: extract alphanumeric parts
  return query.replace(/[^a-zA-Z0-9\s]/g, " ").replace(/\s+/g, " ").trim();
}
```

Update `src/application/services/index.ts`:

2. Add a `searchSummaries()` method that queries `sessions_fts`:
   ```typescript
   /**
    * Search session summaries via FTS5.
    *
    * @param query Search query (sanitized internally for FTS5 safety)
    * @param limit Maximum results (default: 20)
    * @returns Array of sessions whose summaries match the query
    */
   async searchSummaries(query: string, limit: number = 20): Promise<Session[]> {
     const sanitized = sanitizeFtsQuery(query);
     if (!sanitized) return [];
     const rows = this.db.prepare(`
       SELECT s.* FROM sessions s
       JOIN sessions_fts f ON f.session_id = s.id
       WHERE sessions_fts MATCH ?
       ORDER BY rank
       LIMIT ?
     `).all(sanitized, limit);
     return rows.map(r => this.toEntity(r));
   }
   ```
3. This method is added directly to `SqliteSessionRepository` (not to the `ISessionRepository` port). The port can be extended later when the method is needed through domain contracts.

### Refactor Phase

**IMPORTANT architectural note:** Infrastructure importing from application is the WRONG direction in hexagonal architecture. The sanitizer is a pure function with zero dependencies. Two options:
1. Move it to a shared utilities location that both layers can use
2. Accept the pragmatic import since it is a leaf function with no coupling

The correct approach: keep `sanitizeFtsQuery` in application/services (it IS application logic -- query preparation for the search use case). The Fts5SearchService is infrastructure, but it already imports domain types. Importing a pure function from application does not create a circular dependency or coupling issue. This is a pragmatic exception that matches how the codebase already works (e.g., HybridSearchService imports `rrf-fusion` and `temporal-decay` from application/services).
