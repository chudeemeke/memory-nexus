<task type="auto">
  <name>Task 2: Fix ErrorCode frozen test stale count</name>
  <files>src/domain/errors/error-codes.test.ts</files>
  <action>
The test file has two hardcoded counts:
- Line 75: `expect(codes).toHaveLength(19)` -- should be dynamic
- Line 81: `expect(keys.length).toBe(19)` -- should be dynamic

Also, the `ErrorCodeType accepts all error codes` test (lines 52-76) lists only 19 codes but 21 exist (NOT_FOUND and INVALID_STATE are missing).

Fix:

1. In the "ErrorCodeType accepts all error codes" test:
   - Add `ErrorCode.NOT_FOUND` and `ErrorCode.INVALID_STATE` to the `codes` array
   - Replace `expect(codes).toHaveLength(19)` with `expect(codes).toHaveLength(Object.keys(ErrorCode).length)` -- this makes the test resilient to future additions while still verifying the array covers all codes

2. In the "ErrorCode is frozen (immutable)" test:
   - Replace `expect(keys.length).toBe(19)` with `expect(keys.length).toBeGreaterThan(0)` -- the point of this test is that each key equals its value (the loop below), not the count. Or better: remove the count assertion entirely since the loop already validates all keys. The length check adds no value beyond what the loop provides.

3. Add a new test that structurally ensures the codes array stays in sync:

```typescript
test("all ErrorCode values are included in type acceptance test", () => {
    const allCodes = Object.values(ErrorCode);
    // This test fails at compile time if a new code is added to ErrorCode
    // but not to the ErrorCodeType array above. The runtime check below
    // catches it even without TypeScript strict checking.
    expect(allCodes.length).toBe(Object.keys(ErrorCode).length);
});
```

Actually, the simplest resilient approach: replace the explicit array in "ErrorCodeType accepts all error codes" with `Object.values(ErrorCode)` cast to `ErrorCodeType[]`. This ensures compile-time validation (if a value does not match the union, TypeScript errors) while being automatically complete:

```typescript
test("ErrorCodeType accepts all error codes", () => {
    const codes: ErrorCodeType[] = Object.values(ErrorCode);
    expect(codes.length).toBe(Object.keys(ErrorCode).length);
});
```

This is better because adding a new code to ErrorCode automatically includes it in the test. The TypeScript compiler ensures every value satisfies ErrorCodeType.
