# Plan 16-03: CLI Integration, Output Formatting, and Doctor Enhancement

## Goal

Wire the HybridSearchService into the search command with new CLI flags (`--mode`, `--no-vector`, `--no-decay`), extend the output formatter to produce the hybrid metadata envelope for JSON output and per-ranker breakdown for verbose output, extend the doctor command with a "Search Capability" section, and ensure `memory context` and `memory related` automatically benefit from hybrid search via the shared search infrastructure.

## must_haves

- [ ] `memory search "query" --mode hybrid` uses HybridSearchService with hybrid mode
- [ ] `memory search "query" --mode fts` forces FTS-only search
- [ ] `memory search "query" --mode vector` forces vector-only search (errors if no embeddings)
- [ ] `memory search "query"` (no mode flag) uses auto mode (hybrid if embeddings exist, FTS otherwise)
- [ ] `memory search "query" --no-vector` is shorthand for `--mode fts` (DEGRADE-04)
- [ ] `memory search "query" --no-decay` disables temporal decay for that search
- [ ] JSON output includes metadata envelope: `meta` object with `query`, `mode`, `mode_reason`, `total_results`, `embedding_coverage`, `degraded`, `degradation_reason`, `capabilities`, `timing_ms`
- [ ] JSON per-result includes `rank`, `score` (normalized 0-1), `raw_scores` (bm25, cosine, rrf), `source` (fts/vector/both), `highlights`
- [ ] Table output shows normalized 0-1 score; verbose adds per-ranker breakdown
- [ ] Backward compatibility: existing JSON consumers see additive-only changes (no field removals or renames)
- [ ] Empty results: "No results for [query]" (FTS/hybrid), "No semantic matches for [query]" (vector)
- [ ] `memory doctor` includes "Search Capability" section: FTS5 status, sqlite-vec status, embedding count/percentage, provider info, default mode, vector readiness
- [ ] `memory doctor` includes "Embedding status" section: total messages, embedded count, percentage, provider name, model, dimensions
- [ ] Doctor exit codes: 0=OK, 1=degraded but functional, 2=broken
- [ ] `memory context` and `memory related` automatically benefit from hybrid search (no new flags needed -- verified via shared search infrastructure)
- [ ] One-time hint at 0% embedding coverage: "Tip: run 'memory sync --embed' to enable semantic search" (tracked via config flag, shown once)
- [ ] 95%+ coverage at EACH metric for all new and modified files

## Tasks

<task id="16-03-A" title="Search command flags and HybridSearchService wiring (TDD)">

### Context

The existing `search.ts` command creates a `Fts5SearchService` directly and calls `search()`. This task replaces that with `HybridSearchService` creation and passes the new flags through. The `HybridSearchService` is the new default search service -- `Fts5SearchService` is still used internally by `HybridSearchService` for the FTS leg.

**Locked decisions from CONTEXT.md:**
- `--mode auto|fts|vector|hybrid` (default: auto)
- `--no-vector` shorthand for `--mode fts`
- `--no-decay` disable temporal decay for single search
- Both `--mode` and `--no-vector` supported (DEGRADE-04)
- CLI precedence: flags > config > defaults
- `memory context` and `memory related` benefit automatically via shared infrastructure

**Integration with context/related commands:** The `SqliteContextService` uses `Fts5SearchService` internally. To make context/related benefit from hybrid search, either:
(a) Replace `Fts5SearchService` with `HybridSearchService` in context-service construction, OR
(b) Accept that context/related use FTS-only for now and hybrid search benefits come through `memory search` only.

Per CONTEXT.md: "memory context benefits automatically via shared search infrastructure (no new flags)." This means option (a) -- the context service should accept an `ISearchService` (which `HybridSearchService` implements) instead of hardcoding `Fts5SearchService`. Check how `SqliteContextService` is constructed. If it creates `Fts5SearchService` internally, it needs to accept `ISearchService` via constructor injection instead.

**SearchCommandOptions extension:**
```typescript
interface SearchCommandOptions {
  // existing fields...
  mode?: string;
  noVector?: boolean;
  noDecay?: boolean;
}
```

<task id="16-03-B" title="Output formatter hybrid envelope, doctor search section, and exit codes (TDD)">

### Context

This task extends the output formatters to include hybrid search metadata in JSON output and per-ranker breakdown in verbose output. It also extends the doctor command with search capability and embedding status sections, and implements doctor exit codes.

**Locked decisions from CONTEXT.md:**
- JSON output: exhaustive metadata envelope with `meta` + per-result `raw_scores`
- Table output: normalized 0-1 score, verbose adds per-ranker breakdown
- Mode shown in JSON metadata always; in human output only with `--verbose`
- Backward compatibility: additive-only JSON schema changes
- Doctor: "Search Capability" section and "Embedding status" section
- Doctor exit codes: 0=OK, 1=degraded but functional, 2=broken
- Highlighting: FTS matches get highlights, vector-only matches show text without highlights

**JSON output structure (from CONTEXT.md):**
```json
{
  "meta": {
    "query": "auth patterns",
    "mode": "hybrid",
    "mode_reason": "auto_hybrid",
    "total_results": 5,
    "embedding_coverage": 0.85,
    "degraded": false,
    "capabilities": { "fts": true, "vector": true, "hybrid": true },
    "timing_ms": 142
  },
  "results": [
    {
      "rank": 1,
      "session_id": "...",
      "message_id": "...",
      "role": "assistant",
      "timestamp": "...",
      "score": 0.95,
      "raw_scores": { "bm25": -3.2, "cosine": 0.87, "rrf": 0.032 },
      "source": "both",
      "snippet": "...",
      "highlights": [{ "offset": 10, "length": 4 }]
    }
  ]
}
```

**Important:** The existing `OutputFormatter` interface uses `SearchResult[]` as input. The hybrid metadata needs to be passed alongside results. Options:
(a) Add metadata to `FormatOptions` (simplest, keeps interface stable)
(b) Change the formatter interface (breaks existing callers)

Use option (a): extend `FormatOptions` with an optional `searchMeta` field.

   ```typescript
   function extractHighlights(snippet: string): Array<{ offset: number; length: number }> {
     const highlights: Array<{ offset: number; length: number }> = [];
     let cleanText = "";
     let i = 0;
     const raw = snippet;
     while (i < raw.length) {
       if (raw.startsWith("<mark>", i)) {
         i += 6; // skip <mark>
         const end = raw.indexOf("</mark>", i);
         if (end === -1) break;
         highlights.push({ offset: cleanText.length, length: end - i });
         cleanText += raw.substring(i, end);
         i = end + 7; // skip </mark>
       } else {
         cleanText += raw[i];
         i++;
       }
     }
     return highlights;
   }
   ```
