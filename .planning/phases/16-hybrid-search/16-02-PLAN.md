# Plan 16-02: HybridSearchService with Mode Resolution, Query Embedding, and Graceful Degradation

## Goal

Build the `HybridSearchService` that composes the existing `Fts5SearchService` with vector KNN search and RRF fusion to provide four search modes (auto, fts, vector, hybrid). The service resolves the effective mode based on CLI flags, config, and system capabilities. It embeds the query at search time for vector/hybrid modes and degrades gracefully to FTS-only when vector components are unavailable (sqlite-vec missing, no embeddings, provider failure).

## must_haves

- [ ] `HybridSearchService` exists in `src/infrastructure/database/services/hybrid-search-service.ts` implementing `ISearchService`
- [ ] `HybridSearchService.search()` accepts `HybridSearchOptions` (mode, noDecay, plus existing filters)
- [ ] Mode resolution chain: explicit CLI mode > config `search.defaultMode` > `'auto'`
- [ ] Auto mode: uses hybrid when ANY embeddings exist in the database, FTS-only when zero embeddings
- [ ] Explicit `--mode vector` with no embeddings throws `MemoryError(VECTOR_UNAVAILABLE)` with suggestion "Run 'memory sync --embed' first"
- [ ] Explicit `--mode hybrid` with no vector capability degrades to FTS-only (soft degradation, not error)
- [ ] FTS mode: delegates directly to `Fts5SearchService` (zero overhead, no vector path)
- [ ] Vector mode: embeds query via provider, runs KNN on EmbeddingRepository, hydrates results with message metadata
- [ ] Hybrid mode: runs FTS and vector in parallel (conceptually), feeds both to `reciprocalRankFusion()`, applies temporal decay if enabled
- [ ] 4x candidate multiplier: fetches `limit * 4` from each ranker before feeding to RRF
- [ ] Query embedded at search time using the same provider as stored embeddings
- [ ] Provider/model mismatch detection: if stored model hash differs from current config hash, warn to stderr but attempt search if dimensions match; degrade to FTS-only if dimensions differ
- [ ] Graceful degradation when sqlite-vec extension unavailable: auto/hybrid mode -> FTS-only, vector mode -> error
- [ ] Graceful degradation when embedding provider fails to initialize: auto/hybrid mode -> FTS-only, vector mode -> error
- [ ] Graceful degradation with partial embedding coverage: RRF handles structurally (FTS covers all messages, vector covers embedded subset)
- [ ] `search()` returns `SearchResult[]` with populated `source` and `rawScores` fields for each result
- [ ] Search result metadata includes `mode`, `modeReason`, `degraded`, `degradationReason`, `embeddingCoverage`, `capabilities`, `timingMs` -- returned via a separate metadata accessor or extended return type
- [ ] Temporal decay applied after RRF fusion when config `search.temporalDecay.enabled` is true and `noDecay` option is not set
- [ ] Snippet generation: FTS results use FTS5 `snippet()`, vector-only results use first 200 chars of content, hybrid results use FTS5 snippet when available
- [ ] Suggestion strings added to error-formatter for new error codes
- [ ] 95%+ coverage at EACH metric for all new and modified files

### Context

The `HybridSearchService` composes the existing `Fts5SearchService`, `EmbeddingRepository`, and `EmbeddingProviderFactory` into a unified search interface. It implements `ISearchService` from the domain ports layer so it can be a drop-in replacement where `Fts5SearchService` was used.

**Architecture:** This is an infrastructure-layer service (it uses database-specific types). It goes in `src/infrastructure/database/services/` alongside the existing `search-service.ts`. The service receives its dependencies via constructor injection.

**Locked decisions from CONTEXT.md:**
- Auto mode: if ANY embeddings exist -> hybrid, else FTS-only (no threshold)
- Silent degradation in auto mode (search always returns results)
- Explicit `--mode vector` with no embeddings -> error with actionable guidance
- CLI precedence: flags > config > defaults
- 4x candidate multiplier, k=60 RRF (both in Plan 16-01's RRF function)
- Singleton embedding provider (cached via factory)
- Temporal decay after RRF, before final ranking
- One-time hint at 0% coverage (deferred to Plan 16-03 CLI layer)

**Dependencies injected via constructor:**
```typescript
interface HybridSearchDeps {

  fts5Service: Fts5SearchService;
  embeddingRepo: EmbeddingRepository;
  providerFactory: EmbeddingProviderFactory;
  config: MemoryConfig;

}
```

2. **Implement `search()` with mode resolution:**
   ```typescript
   async search(query: SearchQuery, options?: HybridSearchOptions): Promise<SearchResult[]> {
     const startTime = performance.now();
     const mode = this.resolveMode(options?.mode);

     switch (mode.effectiveMode) {
       case 'fts':
         return this.ftsSearch(query, options, mode);
       case 'vector':
         return this.vectorSearch(query, options, mode);
       case 'hybrid':
         return this.hybridSearch(query, options, mode);
     }
   }
   ```

3. **Mode resolution logic** as a private method:
   ```typescript
   private resolveMode(requested?: SearchMode): ResolvedMode {
     const configDefault = this.config.search.defaultMode;
     const mode = requested ?? configDefault;

     if (mode === 'auto') {
       if (!this.sqliteVecAvailable || this.embeddingRepo.getEmbeddedCount() === 0) {
         return { effectiveMode: 'fts', degraded: false, reason: 'no_embeddings' };
       }
       return { effectiveMode: 'hybrid', degraded: false, reason: 'auto_hybrid' };
     }

     if (mode === 'vector') {
       if (!this.sqliteVecAvailable) {
         throw new MemoryError(ErrorCode.VECTOR_UNAVAILABLE,
           'Vector search requires sqlite-vec extension',
           { suggestion: "Run 'memory doctor' to check extension status" });
       }
       if (this.embeddingRepo.getEmbeddedCount() === 0) {
         throw new MemoryError(ErrorCode.VECTOR_UNAVAILABLE,
           'No embeddings found in database',
           { suggestion: "Run 'memory sync --embed' to generate embeddings" });
       }
       return { effectiveMode: 'vector', degraded: false, reason: 'explicit' };
     }

     if (mode === 'hybrid') {
       if (!this.sqliteVecAvailable || this.embeddingRepo.getEmbeddedCount() === 0) {
         return { effectiveMode: 'fts', degraded: true, reason: 'sqlite_vec_unavailable' };
       }
       return { effectiveMode: 'hybrid', degraded: false, reason: 'explicit' };
     }

     // mode === 'fts'
     return { effectiveMode: 'fts', degraded: false, reason: 'explicit' };
   }
   ```

4. **FTS search path:** Delegate to `this.fts5Service.search()` directly.

5. **Vector search path:**
   - Get provider from factory, initialize if not ready
   - Embed the query text
   - Call `this.embeddingRepo.vectorKnnSearch(queryEmbedding, limit * 4)`
   - Hydrate results with message metadata (JOIN messages_meta)
   - Create SearchResult objects with `source: 'vector'`, snippet from first 200 chars

6. **Hybrid search path:**
   - Run FTS search with `limit * 4` candidates
   - Embed query and run vector search with `limit * 4` candidates
   - Wrap in try-catch: if vector leg fails, fall back to FTS results only
   - Convert both to `RankedCandidate[]` (assign rank based on position)
   - Call `reciprocalRankFusion(fts, vector, limit)`
   - Apply temporal decay if enabled and `noDecay` is not set
   - Hydrate fused results and create SearchResult objects

7. **Metadata tracking:** Use a private `lastSearchMeta` field or return an extended type. The simplest approach: store metadata on the service instance after each search, accessible via a `getLastSearchMeta()` getter. The CLI layer reads this after search.

   ```typescript
   interface SearchMeta {
     mode: SearchMode;
     modeReason: string;
     degraded: boolean;
     degradationReason?: string;
     embeddingCoverage: number;
     capabilities: { fts: boolean; vector: boolean; hybrid: boolean };
     timingMs: number;
   }
   ```

8. **Provider mismatch detection:** Before embedding the query, check stored model hash vs current config hash. If dimensions differ, degrade to FTS. If hash differs but dimensions match, warn to stderr and proceed.

9. **Hydration helper:** Query `messages_meta` for session_id, content, timestamp, role by rowid(s):
   ```typescript
   private hydrateByRowids(rowids: number[]): Map<number, MessageMeta> {
     if (rowids.length === 0) return new Map();
     const placeholders = rowids.map(() => '?').join(',');
     const rows = this.db.prepare<MessageMeta, number[]>(`
       SELECT rowid, id, session_id, content, timestamp, role
       FROM messages_meta
       WHERE rowid IN (${placeholders})
     `).all(...rowids);
     return new Map(rows.map(r => [r.rowid, r]));
   }
   ```
