# Plan 14-03: TransformersJsProvider with Lazy Loading and WASM Fallback

## Goal

Implement the `TransformersJsProvider` infrastructure adapter that satisfies the `IEmbeddingProvider` domain port (from 14-01). The provider lazy-loads the ONNX runtime via dynamic import, generates embeddings using all-MiniLM-L6-v2 (384 dimensions), reports download progress on first run, and falls back to WASM backend when native ONNX fails.

## must_haves

- [ ] `TransformersJsProvider` implements `IEmbeddingProvider` from the domain port
- [ ] `@huggingface/transformers@^3.8.1` is added to package.json dependencies
- [ ] The `@huggingface/transformers` module is NEVER imported at the top level -- only via `await import()` inside `initialize()`
- [ ] `initialize()` creates a `feature-extraction` pipeline with `Xenova/all-MiniLM-L6-v2` model, quantized (`dtype: "q8"`)
- [ ] `initialize()` accepts optional `onProgress` callback and forwards Transformers.js progress events as `DownloadProgress` objects (EMBED-06 infrastructure: callback mechanism and unit tests with mocked progress events. CLI wiring — connecting this callback to a visible cli-progress bar — is deferred to Phase 15 where `sync --embed` invokes `provider.initialize(onProgress)`. Phase 15 MUST include this wiring as an explicit task.)
- [ ] When native ONNX runtime fails, `initialize()` falls back to WASM with `numThreads: 1` and logs a warning
- [ ] `embed(text)` returns `EmbeddingResult` with Float32Array of 384 dimensions using mean pooling + normalization
- [ ] `embedBatch(texts)` embeds multiple texts efficiently
- [ ] `isReady()` returns false before `initialize()`, true after
- [ ] `dispose()` cleans up pipeline resources
- [ ] Calling `embed()` before `initialize()` throws a descriptive error
- [ ] Tests mock `@huggingface/transformers` -- no real model downloads during testing
- [ ] 95%+ coverage at EACH metric for new files

## Tasks

<task id="14-03-A" title="TransformersJsProvider core implementation (TDD)">

### Context

The provider is the primary infrastructure adapter for the `IEmbeddingProvider` domain port. It must:
1. Lazy-load the ONNX runtime only when `initialize()` is called (EMBED-05 lazy loading concern, but the implementation is here)
2. Use Transformers.js v3 `pipeline("feature-extraction", ...)` API
3. Return `EmbeddingResult` value objects (from 14-01)

**Research Pattern 2 (Lazy Dynamic Import):** The `@huggingface/transformers` module is imported inside `initialize()` via `await import(...)`. This ensures `memory search "text"` (FTS5-only) never loads the ONNX runtime.

**Research Pitfall 2 (Dynamic Import Caching):** Bun caches dynamic imports. Multiple `initialize()` calls are no-ops if pipeline is already created. This is desirable -- singleton per process.

**Research Pitfall 3 (Float32Array Serialization):** `embed()` must return Float32Array (not number[]). The pipeline output `.tolist()[0]` returns number[], which must be wrapped in `new Float32Array(...)`.

### Green Phase -- Implement

Create `src/infrastructure/embedding/transformers-js-provider.ts`:

```typescript
import type { IEmbeddingProvider, DownloadProgress } from "../../domain/ports/embedding.js";
import { EmbeddingResult } from "../../domain/value-objects/embedding-result.js";

interface TransformersJsProviderOptions {
  model?: string;
  dimensions?: number;
}

export class TransformersJsProvider implements IEmbeddingProvider {
  readonly name = "transformers-js";
  readonly model: string;
  readonly dimensions: number;

  private pipeline: any = null;

  constructor(options?: TransformersJsProviderOptions) {
    this.model = options?.model ?? "Xenova/all-MiniLM-L6-v2";
    this.dimensions = options?.dimensions ?? 384;
  }

  async initialize(onProgress?: (progress: DownloadProgress) => void): Promise<void> {
    if (this.pipeline) return; // Idempotent

    const { pipeline, env } = await import("@huggingface/transformers");
    env.allowLocalModels = false;

    try {
      this.pipeline = await pipeline("feature-extraction", this.model, {
        dtype: "q8",
        progress_callback: onProgress ? (p: any) => {
          onProgress({
            status: p.status === "ready" ? "ready" : p.status === "progress" ? "downloading" : "loading",
            file: p.file,
            loaded: p.loaded,
            total: p.total,
          });
        } : undefined,
      });
    } catch (nativeError) {
      // WASM fallback (EMBED-07)
      console.warn(
        `Native ONNX runtime failed: ${nativeError instanceof Error ? nativeError.message : String(nativeError)}`
      );
      console.warn("Falling back to WASM backend (slower but universal)");
      env.backends.onnx.wasm.numThreads = 1;
      this.pipeline = await pipeline("feature-extraction", this.model, {
        dtype: "q8",
        device: "wasm",
      });
    }
  }

  async embed(text: string): Promise<EmbeddingResult> {
    if (!this.pipeline) {
      throw new Error("Provider not initialized. Call initialize() before embed().");
    }
    const output = await this.pipeline(text, { pooling: "mean", normalize: true });
    const embedding = new Float32Array(output.tolist()[0]);
    return EmbeddingResult.create({
      embedding,
      model: this.model,
      dimensions: this.dimensions,
    });
  }

  async embedBatch(texts: string[]): Promise<EmbeddingResult[]> {
    // Process sequentially to manage memory -- batch optimization deferred to Phase 15
    const results: EmbeddingResult[] = [];
    for (const text of texts) {
      results.push(await this.embed(text));
    }
    return results;
  }

  async isReady(): Promise<boolean> {
    return this.pipeline !== null;
  }

  async dispose(): Promise<void> {
    this.pipeline = null;
  }
}
```

<task id="14-03-B" title="Download progress forwarding and WASM fallback path (TDD)">

### Context

This task adds dedicated tests and implementation refinements for EMBED-06 (progress indicator) and EMBED-07 (WASM fallback). The core provider from task A provides the structure; this task focuses on the two specific behavioral requirements.

**Research Pattern 3 (WASM Fallback):** When the native ONNX pipeline construction throws, catch the error, configure `env.backends.onnx.wasm.numThreads = 1`, and retry with `device: "wasm"`.

**Research Pitfall 4 (WASM Thread Count):** WASM defaults to multi-threaded mode using SharedArrayBuffer, which can fail. Explicitly set `numThreads = 1` for reliability.
