# Plan 14-01: Domain Embedding Port and Value Objects

## Goal

Define the `IEmbeddingProvider` port interface and supporting value objects in the domain layer with zero external dependencies, following the established hexagonal patterns from `ISearchService` and `SearchQuery`/`SearchResult`.

## must_haves

- [ ] `IEmbeddingProvider` interface exists in `src/domain/ports/embedding.ts` with `embed`, `embedBatch`, `isReady`, `initialize`, `dispose` methods and `name`, `dimensions`, `model` readonly properties
- [ ] `EmbeddingResult` value object exists with `embedding` (Float32Array), `model` (string), `dimensions` (number) fields
- [ ] `EmbeddingConfig` value object exists with `enabled` (boolean), `provider` (string), `model` (string), `dimensions` (number) fields and validation
- [ ] `DownloadProgress` interface exists with `status`, `file`, `loaded`, `total` fields
- [ ] Domain port file has ZERO imports from infrastructure or external packages
- [ ] All types are exported via `src/domain/ports/index.ts` and `src/domain/value-objects/index.ts`
- [ ] All tests pass with 95%+ coverage at EACH metric for new files

## Tasks

<task id="14-01-A" title="EmbeddingResult and EmbeddingConfig value objects (TDD)">

### Context

The project uses immutable value objects with private constructors and static factory methods (see `SearchQuery.from()`, `SearchResult.create()`). Value objects validate on construction and are equality-compared by value.

### Red Phase -- Write Failing Tests

Create `src/domain/value-objects/embedding-result.test.ts`:
- Test `EmbeddingResult.create()` with valid Float32Array, model string, dimensions number
- Test that `embedding` getter returns a Float32Array (not number[])
- Test that `dimensions` must match `embedding.length` (throws on mismatch)
- Test that `model` cannot be empty string (throws)
- Test immutability: modifying the input Float32Array after creation does not affect the value object
- Test equality: two EmbeddingResults with same data are equal

Create `src/domain/value-objects/embedding-config.test.ts`:
- Test `EmbeddingConfig.create()` with valid config object `{ enabled: true, provider: "local", model: "Xenova/all-MiniLM-L6-v2", dimensions: 384 }`
- Test default creation via `EmbeddingConfig.defaults()` returns `{ enabled: true, provider: "local", model: "Xenova/all-MiniLM-L6-v2", dimensions: 384 }`
- Test validation: dimensions must be positive integer (throws on 0, negative, float)
- Test validation: provider must be non-empty string
- Test validation: model must be non-empty string
- Test immutability: all getters return the correct values

### Green Phase -- Implement

Create `src/domain/value-objects/embedding-result.ts`:
- Private constructor, static `create(params: { embedding: Float32Array; model: string; dimensions: number })` factory
- Validate `dimensions === embedding.length`, model non-empty
- Copy the Float32Array on construction (`new Float32Array(embedding)`) for immutability
- Getters for all fields

Create `src/domain/value-objects/embedding-config.ts`:
- Private constructor, static `create(params: { enabled: boolean; provider: string; model: string; dimensions: number })` factory
- Static `defaults()` factory returning default config (enabled: true, provider: "local", model: "Xenova/all-MiniLM-L6-v2", dimensions: 384)
- Validate: dimensions > 0 and integer, provider non-empty, model non-empty
- Getters for all fields

Update `src/domain/value-objects/index.ts`:
- Add `export { EmbeddingResult } from "./embedding-result.js";`
- Add `export { EmbeddingConfig } from "./embedding-config.js";`

### Refactor Phase

- Ensure consistent error messages with existing value objects (e.g., SearchQuery throws "Query cannot be empty")
- Verify no external imports in either file

<task id="14-01-B" title="IEmbeddingProvider port interface and contract tests (TDD)">

### Context

Existing port pattern: `src/domain/ports/services.ts` defines `ISearchService` with method signatures using domain types only. `src/domain/ports/ports.test.ts` tests structural conformance by creating mock implementations.

### Red Phase -- Write Failing Tests

Create `src/domain/ports/embedding.test.ts`:
- Test that a mock `IEmbeddingProvider` can be created satisfying the interface contract:
  - `name` readonly property (string)
  - `dimensions` readonly property (number)
  - `model` readonly property (string)
  - `embed(text: string)` returns `Promise<EmbeddingResult>`
  - `embedBatch(texts: string[])` returns `Promise<EmbeddingResult[]>`
  - `isReady()` returns `Promise<boolean>`
  - `initialize(onProgress?: (progress: DownloadProgress) => void)` returns `Promise<void>`
  - `dispose()` returns `Promise<void>`
- Test that `DownloadProgress` type has fields: `status` ("downloading" | "loading" | "ready"), optional `file`, optional `loaded`, optional `total`
- Test that `EmbeddingModelInfo` type has fields: `name` (string), `dimensions` (number), `provider` (string)
- Test mock flow: `initialize()` -> `isReady()` returns true -> `embed("test")` returns valid EmbeddingResult -> `dispose()`

### Green Phase -- Implement

Create `src/domain/ports/embedding.ts`:
- Define `DownloadProgress` interface: `{ status: "downloading" | "loading" | "ready"; file?: string; loaded?: number; total?: number }`
- Define `EmbeddingModelInfo` interface: `{ name: string; dimensions: number; provider: string }`
- Define `IEmbeddingProvider` interface with all methods and readonly properties listed above
- ZERO external imports -- only import `EmbeddingResult` from `../value-objects/embedding-result.js`

Update `src/domain/ports/index.ts`:
- Add exports: `export type { IEmbeddingProvider, DownloadProgress, EmbeddingModelInfo } from "./embedding.js";`

Update `src/domain/ports/ports.test.ts`:
- Add a new `describe("IEmbeddingProvider")` block with mock implementation test (following the existing pattern for ISessionRepository etc.)

### Refactor Phase

- Verify the port file has zero imports from `@huggingface/transformers`, `sqlite-vec`, or any other external package
- Ensure all new types are re-exported through `src/domain/ports/index.ts`
