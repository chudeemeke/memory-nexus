# Phase 38.2 Plan: Redaction, Privacy Governance, and Audit Commands

**Date:** 2026-06-05
**Status:** Complete
**Requirements:** SEC-05, SEC-06, SEC-07, SEC-09
**Depends on:** Phase 38.1 Canonical Event Kernel and Projection Replay

## Intent

Make privacy controls load-bearing before remote sync, external provider egress, and later derived-memory phases. No current implemented, documented, inferred, disabled, or prototype feature is removed. Incomplete surfaces must either be completed in this phase or assigned to a later explicit gate.

## Non-Negotiable Invariants

1. No command, JSON output, log, audit report, or remediation report may print raw detected secrets.
2. Redaction runs before durable storage, FTS indexing, embedding, extraction, export, logs, remote sync, and provider egress.
3. Existing sensitive content can be discovered and remediated without hidden mutation.
4. Remediation is explicit and evidence-producing: scan is default read-only; database redaction and event-log quarantine require flags.
5. Event logs are not silently deleted. Active logs can be replaced with sanitized copies only after raw originals are moved into a quarantine directory.
6. Provider egress policy is explicit, host-aware, and visible in status/doctor output.
7. Existing provider support remains explicit and typed; no broad plugin loader is introduced in this phase.
8. Tests are written against public command/service behavior, not private implementation details.

## Research Baseline

Primary standards checked for this phase:

- OWASP LLM02:2025 treats sensitive information disclosure across prompts, conversations, retrieval, outputs, and logs as a first-order AI application risk.
- OWASP Logging guidance requires secrets and sensitive credentials to be excluded or transformed before log emission.
- NIST AI RMF frames governance, measurement, provenance, and risk management as ongoing controls rather than one-time documentation.

Applied locally: default redaction, explicit egress controls, auditability, user-visible remediation, and no hidden provider leakage.

## Implementation Slices

### 1. Redaction policy hardening

- Extend redaction findings with stable hashed placeholders, rule version, and optional context.
- Add missing high-value patterns: Tailscale keys and key-name based JSON values such as `apiKey`, `token`, `secret`, `password`, and `credential`.
- Preserve existing redaction behavior while improving dedupe and audit evidence.

### 2. Privacy audit and remediation service

- Add a scanner that inspects sensitive database columns and active event logs.
- Report counts and locations only: table, column, row id, event file, line number, kind, placeholder.
- Add explicit remediation modes:
  - `--redact-db`: rewrite mutable database fields with redacted values.
  - `--quarantine-events`: move raw event-log files into a quarantine directory and write sanitized active replacements.
  - `--report <path>`: write a redacted evidence report.
- Rebuild FTS indexes after database remediation so old tokens cannot remain searchable.

### 3. `memory audit-secrets`

- Add a top-level system command with text and JSON output.
- Default behavior is read-only scanning.
- Exit codes:
  - `0`: no findings, or remediation completed without findings remaining.
  - `1`: findings exist and no remediation flag was provided.
  - `2`: operational failure.
- UX expectations: concise text summary, structured JSON envelope, explicit next commands, no raw secrets.

### 4. Provider egress policy

- Add explicit provider-egress policy to config with:
  - provider consent state.
  - remote host allowlist.
  - local-provider exemptions.
- Block remote embedding/extraction provider creation when consent or allowlist is missing.
- Surface warnings and readiness through status/doctor.
- Keep `apiKeyRef` opaque; do not resolve raw secrets.

### 5. Missed egress/log paths

- Redact active facts before extraction embedding comparison.
- Sanitize extraction-provider error logging.
- Redact hook/sync log fields before JSONL persistence.
- Ensure friction entries and fallback ingestion are redacted before storage.
