# Plan 18-01: Build Infrastructure and API Export Surface

## Goal

Create a dual-build system (CLI binary via `bun build` + library entry via `tsc`) and export all execute*Command functions with their typed option interfaces from `src/index.ts`, so that a consumer can `import { executeSyncCommand } from "@chude/memory"` and get full TypeScript types.

## Context

The codebase currently has:
- 16 `execute*Command` functions already exported from `src/presentation/cli/commands/index.ts`
- `package.json` declares `"main": "dist/index.js"` and `"types": "dist/index.d.ts"` but only builds the CLI binary to `dist/presentation/cli/index.js`
- `src/index.ts` only exports domain and application layers, not the presentation execute* functions
- 9 of 16 command option interfaces are private (not exported): SyncCommandOptions, SearchCommandOptions, ListCommandOptions, StatsCommandOptions, ContextCommandOptions, RelatedCommandOptions, ShowCommandOptions, BrowseCommandOptions, DoctorOptions
- 7 interfaces are already exported: PurgeCommandOptions, PurgeResult, EmbeddingPassDeps, BackgroundModeDeps, InstallOptions (implicit via execute signature), UninstallOptions (implicit), ExportOptions/ImportOptions (implicit)
- `tsconfig.json` already has `declaration: true`, `declarationMap: true`, `outDir: "dist"`, `rootDir: "src"` but the build script uses `bun build` (which ignores these settings)

The gap: `dist/index.js` does not exist. No consumer can import from `@chude/memory` as a library.

**Scope note:** 20 files are listed in files_modified, but 16 of those are mechanical single-line changes (`interface Foo` -> `export interface Foo`). The actual implementation complexity is concentrated in `src/index.ts`, `tsconfig.lib.json`, `package.json`, and the smoke test.

## must_haves

- All 16 command option interfaces are exported from their respective command files
- `src/index.ts` re-exports all 16 execute*Command functions and `CommandResult` type from `src/presentation/cli/commands/index.ts`
- `src/index.ts` re-exports all 16 option type interfaces
- `tsconfig.lib.json` extends `tsconfig.json` with library-specific settings
- `package.json` has `build:lib` (tsc), `build:cli` (bun build), and `build` (both in correct order: lib first, cli second)
- After `bun run build`, `dist/index.js` exists and is importable
- After `bun run build`, `dist/index.d.ts` exists with TypeScript declarations
- `dist/presentation/cli/index.js` starts with `#!/usr/bin/env bun` (bun build output, not tsc output)
- A smoke test verifies `dist/index.js` is importable and exports the expected functions

### Task 2: Dual build system and dist verification

Create `tsconfig.lib.json`, update `package.json` build scripts, verify the dist output.

#### Step 1: Create tsconfig.lib.json

Create `tsconfig.lib.json` at the project root:

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "outDir": "dist",
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "noEmit": false
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist", "**/*.test.ts"]
}
```

**Why a separate file:** The main `tsconfig.json` is used by the IDE and `tsc --noEmit` for type-checking. It does not have `noEmit: false` explicitly but the `typecheck` script passes `--noEmit`. A separate lib config avoids ambiguity and can be targeted by `tsc --project tsconfig.lib.json` without affecting the IDE experience.

Note: The main `tsconfig.json` already has `declaration: true`, `declarationMap: true`, `sourceMap: true`, `outDir: "dist"`, `rootDir: "src"`. The only setting the lib config truly needs to override is ensuring `noEmit` is `false` (since the typecheck script uses `--noEmit` flag, not tsconfig's noEmit field, this is defensive).

#### Step 2: Update package.json build scripts

Replace the `scripts.build` entry and add `build:lib` and `build:cli`:

```json
{
  "scripts": {
    "build:lib": "tsc --project tsconfig.lib.json",
    "build:cli": "bun build src/presentation/cli/index.ts --outdir dist/presentation/cli --target bun --external onnxruntime-node",
    "build": "bun run build:lib && bun run build:cli",
    "build:hook": "bun build src/infrastructure/hooks/sync-hook-script.ts --outfile=dist/sync-hook.js --target=bun",
    "test": "bun test",
    "test:coverage": "bun test --coverage",
    "test:smoke": "bun test tests/smoke",
    "typecheck": "tsc --noEmit",
    "lint": "tsc --noEmit",
    "mutation": "stryker run",
    "mutation:domain": "stryker run --mutate 'src/domain/**/!(*.test).ts'"
  }
}
```

**Critical ordering:** `build:lib` (tsc) runs first, then `build:cli` (bun build). The bun build step overwrites `dist/presentation/cli/index.js` with the bundled CLI binary, which is correct. The tsc version of that file would not work as a CLI entry point (no bundling, no shebang).

    it("can import executeSearchCommand from dist", async () => {
