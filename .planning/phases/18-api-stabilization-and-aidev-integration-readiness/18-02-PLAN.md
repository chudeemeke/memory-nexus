#### Implementation notes

- Use `beforeAll` to generate test sessions via `generateTestSessions()` and sync once. **Capture a session ID** from the synced data for use in show, related, export/import tests
- Use `afterAll` to clean up test data (including any temp files created for export/import)
- Each test should be independent (no test-order dependencies within a group)
- Use `quiet: true` on all calls to suppress stdout noise during test runs
- The goal is verifying the API contract (return types, no crashes, exitCode semantics), not testing the underlying logic (that is covered by unit tests)
- Do NOT test executeBrowseCommand -- it requires interactive TTY input via `@inquirer/select` and will hang in test
- For install/uninstall: these modify the user's Claude Code settings.json. The tests verify return type shape only. If hooks are already installed, install returns exitCode 0 (idempotent). If not installed, uninstall returns gracefully.
- For purge: use `dryRun: true` to prevent data loss. Use `olderThan: "999y"` (999 years) so nothing matches the cutoff, verifying the command runs without deleting test data
- For export/import: use `os.tmpdir()` for the export path to avoid filesystem side effects. Clean up temp files in afterAll.

### Task 2: JSDoc and README documentation

Add comprehensive JSDoc to all execute*Command functions and their option interfaces. Add a "Programmatic API" section to README.md.

#### Step 1: JSDoc on execute*Command functions

Add JSDoc to each execute* function. Follow this pattern for each:

```typescript
/**
 * Execute the sync command programmatically.
 *
 * Syncs Claude Code sessions from JSONL files into the SQLite database.
 * Handles its own database initialization and teardown.
 *
 * @param options - Sync options
 * @returns CommandResult with exitCode 0 (success) or 1 (error)
 */
```

Apply to all 16 files. Each JSDoc should:
- State what the command does in one sentence
- Note that it handles its own DB init/teardown
- Document `@param` with the option type name
- Document `@returns` with exitCode semantics (0 = success, 1 = error/not found)
- For functions with positional arguments (search query, context project, show sessionId, related sessionId, export outputPath, import inputPath, completion shell), document those as separate `@param` entries

Specific JSDoc for each execute* function:

1. **executeSyncCommand(options)** - Syncs Claude Code sessions from JSONL files into the SQLite database. Optionally generates embeddings with `embed: true`.

2. **executeSearchCommand(query, options)** - Searches sessions using FTS5 or hybrid semantic search. `query` is the search string (must be non-empty).

3. **executeListCommand(options)** - Lists sessions with optional filtering by project, date range, or limit.

4. **executeStatsCommand(options)** - Shows database statistics including session count, message count, and storage size.

5. **executeContextCommand(project, options)** - Shows aggregated context for a project. `project` is the project name or substring to filter by.

6. **executeRelatedCommand(sessionId, options)** - Finds sessions related to a given session by shared topics and entities. `sessionId` identifies the source session.

7. **executeShowCommand(sessionId, options)** - Shows detailed information about a specific session. `sessionId` identifies the session to display.

8. **executeBrowseCommand(options)** - Interactively browse sessions using fuzzy search. Requires an interactive TTY; will hang in non-interactive environments.

9. **executeInstallCommand(options)** - Installs Claude Code hooks for automatic session sync on session end.

10. **executeUninstallCommand(options)** - Removes Claude Code hooks installed by the install command.

11. **executeStatusCommand(options)** - Shows current hook installation status and embedding progress.

12. **executeDoctorCommand(options)** - Runs health checks on the database, hooks, FTS5, sqlite-vec, and embedding provider.

13. **executePurgeCommand(options)** - Purges sessions from the database matching specified criteria (age, project, or pattern).

14. **executeExportCommand(outputPath, options)** - Exports the database to a file. `outputPath` is the destination file path.

15. **executeImportCommand(inputPath, options)** - Imports a previously exported database file. `inputPath` is the source file path.

16. **executeCompletionCommand(shell)** - Outputs shell completion script for the specified shell (bash, zsh, or fish).

#### Step 2: JSDoc on option interfaces

```typescript
/**
 * Options for the sync command.
 */
export interface SyncCommandOptions {
  /** Force re-sync of all sessions, ignoring extraction state */
  force?: boolean;
  /** Filter to sessions from a specific project */
  project?: string;
  /** Filter to a specific session by ID */
  session?: string;
  /** Suppress non-essential output */
  quiet?: boolean;
  /** Show detailed output with timing information */
  verbose?: boolean;
  /** Output results as JSON */
  json?: boolean;
  /** Preview sync without modifying the database */
  dryRun?: boolean;
  /** Fix project names using the resolver */
  fixNames?: boolean;
  /** Generate embeddings for synced messages */
  embed?: boolean;
  /** Run embedding generation in a background process */
  background?: boolean;
}
```

Apply the same pattern to all option interfaces: SyncCommandOptions, SearchCommandOptions, ListCommandOptions, StatsCommandOptions, ContextCommandOptions, RelatedCommandOptions, ShowCommandOptions, BrowseCommandOptions, InstallOptions, UninstallOptions, DoctorOptions, PurgeCommandOptions, ExportOptions, ImportOptions, StatusOptions (if it exists as an interface), GatherStatusOptions.
