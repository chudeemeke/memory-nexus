<objective>
Create centralized XDG-aware path module and legacy migration module, then rewire all infrastructure modules to use centralized paths instead of scattered homedir() + ".memory-nexus" constructions.

Purpose: Establishes the path foundation for the entire rename. Currently 6 infrastructure modules each construct their own paths using `join(homedir(), ".memory-nexus", ...)`. This plan centralizes all paths into a single module that respects XDG conventions (`~/.config/memory/` for config, `~/.local/share/memory/` for data), and creates the migration module that moves existing user data from legacy paths to new paths with rollback safety.

Output: paths.ts, migration.ts (with tests), all 6 infrastructure modules rewired to delegate path resolution.
</objective>

    TDD: Write tests first, then implementation.

    **paths.ts** -- Create a centralized path module as the single source of truth for all filesystem paths. The module defines:

    - `APP_NAME = "memory"` constant (not exported, internal only)
    - `getConfigDir()`: Returns `$XDG_CONFIG_HOME/memory` if XDG_CONFIG_HOME is set, otherwise `~/.config/memory`
    - `getDataDir()`: Returns `$XDG_DATA_HOME/memory` if XDG_DATA_HOME is set, otherwise `~/.local/share/memory`
    - `getLegacyDir()`: Returns `~/.memory-nexus` (for migration detection)
    - `getConfigPath()`: Returns `getConfigDir()/config.json`
    - `getDbPath()`: Returns `getDataDir()/memory.db`
    - `getLogDir()`: Returns `getDataDir()/logs`
    - `getHookDir()`: Returns `getDataDir()/hooks`
    - `getBackupDir()`: Returns `getDataDir()/backups`
    - `getCheckpointPath()`: Returns `getDataDir()/sync-checkpoint.json`

    Each function must support a test override mechanism. Use the same pattern as existing modules (a `let testOverrideDir: string | null = null` with `setTestPaths(overrides)` / `resetTestPaths()` functions). The test override should allow overriding the base config dir and data dir independently so tests can isolate paths without touching the real filesystem.

    Import `homedir` from `node:os` and `join` from `node:path`. No other dependencies (domain layer purity is not required for infrastructure, but keep it minimal).

    **paths.test.ts** -- Test cases:
    - Default paths use `~/.config/memory` and `~/.local/share/memory`
    - XDG_CONFIG_HOME override changes config dir but not data dir
    - XDG_DATA_HOME override changes data dir but not config dir
    - Both XDG vars set simultaneously
    - getLegacyDir() always returns `~/.memory-nexus` regardless of XDG vars
    - All derived paths (getConfigPath, getDbPath, etc.) derive from their parent dir functions
    - Test override mechanism works correctly

    For XDG env var tests: save, set, and restore `process.env.XDG_CONFIG_HOME` and `process.env.XDG_DATA_HOME` in beforeEach/afterEach. Use the test override mechanism for path isolation.

    **migration.ts** -- Create a migration module with:

    - `MigrationStatus` type: `"not-needed" | "pending" | "complete" | "partial"`
    - `MigrationResult` interface: `{ migrated: boolean; itemsMoved: string[]; errors: string[] }`
    - `getMigrationStatus()`: Check if legacy dir exists and if new paths exist. Returns `{ legacyExists: boolean; newExists: boolean; status: MigrationStatus }`
    - `migrateFromLegacy()`: Performs the migration with rollback. Steps:
      1. Check if legacy dir exists. If not, return `{ migrated: false, itemsMoved: [], errors: [] }`
      2. Ensure new config dir and data dir exist (mkdirSync recursive)
      3. Define move list (ordered by priority per research): DB first, config second, checkpoint, logs, hooks, backups
      4. For each item: check if source exists, attempt `renameSync`. On EXDEV error, fall back to `cpSync`/`copyFileSync` + `rmSync`/`unlinkSync`. Track completed moves.
      5. On any move failure: roll back all completed moves (reverse order, move back to source). Return error result.
      6. On success: attempt to remove empty legacy directory. Print one-line notice to stderr.
      7. Return success result with list of moved items.

    The migration move list maps legacy paths to new paths:
    - `~/.memory-nexus/memory.db` -> `getDataDir()/memory.db`
    - `~/.memory-nexus/config.json` -> `getConfigDir()/config.json`
    - `~/.memory-nexus/sync-checkpoint.json` -> `getDataDir()/sync-checkpoint.json`
    - `~/.memory-nexus/logs/` -> `getDataDir()/logs/` (directory move)
    - `~/.memory-nexus/hooks/` -> `getDataDir()/hooks/` (directory move)
    - `~/.memory-nexus/backups/` -> `getDataDir()/backups/` (directory move)

    For directory moves, use the same renameSync-with-EXDEV-fallback pattern. For the EXDEV fallback on directories, use `cpSync(src, dest, { recursive: true })` followed by `rmSync(src, { recursive: true })`.

    Import from `node:fs`: existsSync, mkdirSync, renameSync, cpSync, rmSync, readdirSync, unlinkSync, copyFileSync, statSync.
    Import from paths.ts: getConfigDir, getDataDir, getLegacyDir, getConfigPath, getDbPath, etc.

    **migration.test.ts** -- Test cases:
    - `getMigrationStatus()` returns "not-needed" when no legacy dir exists
    - `getMigrationStatus()` returns "pending" when legacy dir exists but new paths don't
    - `getMigrationStatus()` returns "complete" when new paths exist and no legacy dir
    - `getMigrationStatus()` returns "partial" when both legacy and new paths exist
    - `migrateFromLegacy()` moves all files from legacy to new XDG paths
    - `migrateFromLegacy()` rolls back on failure (simulate failure by making target dir read-only or similar)
    - `migrateFromLegacy()` handles EXDEV by falling back to copy+delete (hard to test directly, but test the internal moveFileOrDir helper)
    - `migrateFromLegacy()` is a no-op when legacy dir doesn't exist
    - `migrateFromLegacy()` removes empty legacy dir after successful migration
    - `migrateFromLegacy()` handles individual missing items gracefully (e.g., no logs dir in legacy)

    Use temp directories (Bun's `import { tmpdir } from "node:os"` + `mkdtempSync`) for all test filesystem operations. Override paths.ts test paths to point at temp dirs.
