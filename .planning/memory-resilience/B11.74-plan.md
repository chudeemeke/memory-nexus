# B11.74 - Deterministic native database closure

Status: active. Owner: memory-nexus. Discovered during B11.4 at 0423e45.

The end state is a closed connection whose owned statements no longer retain
native database handles. Cleanup must not depend on the next test, garbage
collection, an unbounded wait or process exit. Preserve storage ownership,
committed data, rollback behavior and useful errors.

The actual shared-close retained-statement regression was RED. A factory-owned

native resources. Ten native cases and the current-runtime 54-test group passed,
but the older-runtime command group still intermittently failed. A status catch
observation identified a swallowed `database is locked` before cleanup EBUSY.

The decisive smaller synthetic probe uses only SELECT 1, collection pressure and
real files. Weak tracking failed on Windows Bun 1.3.14 at iteration zero, with
148 tracking entries but only 78 wrappers and 79 native objects reachable.
The paired strong-wrapper control passed 20 iterations of 500 statements.
This proves that weak tracking is insufficient, without asserting an unobserved
engine destructor schedule. Neither health checks nor real memory data are
required to reproduce this failure. Explicit native table-valued PRAGMA disposal
passed 100 iterations; full-schema/stats variants also passed their smaller loop.

Required truths are unchanged: every live native resource needs a reachable
owner until explicit disposal; one-off work must not accumulate for a long-lived
connection; closure must preserve data/rollback and report failures; compatibility
cannot depend on a newer runtime accidentally cleaning up for us. Weak references
do not satisfy the first requirement. The earlier selection overvalued a smaller
diff before proving the lifetime boundary.

The minimum reliable direction is explicit ownership plus scope disposal, using
the native statement API. A per-connection strong owner can supply final closure,
but it is NOT sufficient until one-off/hot-loop callers release statements and
remove their ownership entries. Do not ship an indefinitely growing registry.
Avoid native `.native` ABI dependencies: installed Bun typings explicitly leave
that API unstable. Do not replace every prepare with query: cache overflow still
creates uncached statements.
