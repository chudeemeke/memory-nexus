# Historical UAT checker disposition

Decision: retire `scripts/run-uat-verification.ts` and its dedicated regression
driver. Preserve their history/evidence and carry needed product outcomes into
the installed-package acceptance barrier. Owner: memory-nexus. Date: 2026-09-20.

## Why this is the appropriate scope

The script was introduced by release commit `03d92d8` on 2026-05-25. Before the
present repair work it had no subsequent changes. It is not a package script,
published file, library entrypoint or documented supported command. Current
repository analysis resolves 2603 imports/references across 446 JS/TS files: the
only reverse imports are two imports from its own new test driver. Three positive
resolver controls pass. Both other computed imports resolve to `dist/index.js`.
Executable text references also occur only in the dedicated driver; planning
references describe this repair. This is a repository/package finding, not a claim
that nobody has ever run the file manually.

The historical checker launches whichever global `memory` resolves on PATH while
rebuilding its database using this checkout's source modules. It does not pin or
verify a common artifact identity. Its old release-approval claim was unsupported.
Some checks are indirect: absence of a legacy directory does not prove absence of
legacy reads, and injected legacy facts do not establish complete v2 portable
recovery. The fixes and synthetic tests are useful evidence about these mistakes,
but extending this manual checker with process-tree supervision and generated-code
coverage would preserve the wrong acceptance architecture.

Retirement removes this executable and its private five-function API. Shared owned
storage/database helpers and all product tests remain. It is not a coverage
exclusion, a coverage pass, or a claim that replacement acceptance is complete.

These tests are not claimed freshly passing or sufficient for installed acceptance.
Several retain cleanup defects already owned by other B11 tasks. The published
package verifier is also not a replacement: it primarily checks versions and has
separate cleanup/isolation gaps. Do not run it as a substitute for these outcomes.

D04 is refined into dependency-linked children. B10 additionally depends on D04,
and R02 already depends on both B10 and D04. Thus neither baseline quality closure
nor final baseline review can skip the displaced acceptance work. No child is
marked verified by this document. No new public API, production replication, real
data egress or release is authorized by this disposition.

If a required recovery route is absent from the packaged artifact, that is an
explicit failed admission or design boundary, not permission to import arbitrary
checkout source and claim an installed pass. Source-level proof and installed
proof must remain separately identified.
