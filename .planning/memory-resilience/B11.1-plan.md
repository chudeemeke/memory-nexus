# B11.1 - Owned database fixture cleanup

Status: active. Starting source: 61c757543638b6249dfaa6fed7e5ccaecd575511.

The helper currently marks cleanup complete before close/removal, discards both
failures and deletes whatever occupies its temporary path. This repair is test
infrastructure only. Existing/replaced directories must survive cleanup; failed
cleanup must remain diagnosable and retryable. Reboot reclamation is not assumed.

1. Reproduce replacement deletion through createTestDir using a newly allocated
   synthetic fixture; preserve recovery handles and explicitly reclaim only
   verified probe-owned paths.
2. Introduce one reusable owned temporary-directory primitive for both helpers.
   Bind exclusive allocation to canonical parent/path, directory identity and an
   exclusive ownership marker. Verify before deletion. Preserve ownership after
   partial removal only when the original directory identity still matches.
3. Make database cleanup close once after successful closure, retry failed close
   or removal, and reclaim initialization failures without hiding the primary
   error. Existing callers keep the same create/cleanup interface; cleanup failure
   now throws a path-bearing error instead of silently succeeding.
4. Exercise real SQLite success, repeated cleanup, replacement/link/marker
   refusal, close/init/removal failure and partial cleanup recovery. Use local
   dependency injection for failure boundaries, not process-wide module mocks.
5. Refresh changed/new inventory entries as proposed and invalidate their older
   metric evidence. Run focused caller checks and targeted type checking; record
   remaining platform, complete Tier S metrics and independent-review obligations.
